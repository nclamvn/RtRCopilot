## Contract and hard floors

- **Standalone:** a neutral entry, layout, metadata, local launcher and independent
  build graph. Existing legacy entry remains available and selected regressions
  stay green. Loopback only; no downloaded font or telemetry. Local build/start
  validation is not deployment. The launcher must clean up its child processes.
- **Snapshot:** support `agent-workspace-export-v1` produced by AW-04. Preview
  contents and omissions before import; validate exact member list, hashes,
  lengths, schema, IDs/relationships and bounded archive sizes/counts before any
  application mutation. Reject corruption, traversal, symlinks, duplicate names,
  unexpected/encrypted members, zip bombs and unsupported formats explicitly.
  The format is not trusted authority merely because it has a manifest/hash.
- **Atomic new identity:** import only into a NEW workspace owned by the current
  session. Fresh resource IDs, structured lineage/remapping, byte-exact original
  files and artifact content/versions. Preserve displayed message order but do
  not revive model checkpoints or incomplete runs. No source/owner ID may become
  live authority. Preview/commit binds exact archive digest, choices, owner and
  expiry; lost ACK is idempotent, changed arguments conflict, partial failures
  roll back. No overwrite/import-into-existing-workspace feature in this milestone.
- **No resurrected power:** never import credentials, grants, approvals, receipts,
  active schedules/execution or session identity. Saved memory is opt-in in the
  preview and imported as an explicit user action, not silent cache restoration.
  Explain retained audit/backup limits and archived conversation versus resumable
  execution. Preserve supported data or reject clearly, never silently truncate.
- **Daily navigation:** search/filter owned workspaces, rename, archive/unarchive,
  restore visibility. Archive is not deletion or an approval/revocation mechanism;
  define its busy/write behavior consistently at server and UI. Retain source,
  output/version access. No semantic index, new file formats or quota inflation.
- **Drafts and stale work:** composer drafts belong to workspace and are restored
  on reload. Blank/sent/deleted drafts cannot reappear from late async callbacks;
  switching while upload/ACK/import/save is pending must not mutate the selected
  project's data, draft or rail. Storage failure gives honest unsaved guidance.
  Imported IDs cannot collide with another workspace's browser cache.

## Completion / Verify

### User outcomes and coverage

All four approved local technical outcome groups are implemented:

1. `@agent-workspace/web` has its own neutral Next entry/layout/reset, package,
   local build and launcher. It imports shared neutral UI/BFF only, not the
   legacy shell, CSS cascade, auth, proxy, company corpus or services. The legacy
   application was not deleted/migrated. Offline pinned-package linking succeeded;
   the initial store/metadata-cache resolution aborts were resolved using the
   existing exact lock/store without a fetch or module purge.
2. AW-04 v1 snapshots can be previewed and imported atomically into a NEW owned
   workspace. Original file bytes, extracted text, every supported artifact
   version and displayed message order are preserved, with fresh IDs and scoped
   lineage. Memory defaults off and requires explicit opt-in. Credentials,
   sessions, grants, approvals, receipts, running jobs, schedules and reusable
   model checkpoints never become active state. Imported statements/checksums
   are not source authority. The original and unrelated workspaces stay intact.
3. Owned workspace finding, rename and archive/unarchive are available. Metadata
   uses revision/CAS and idempotent requests. Archive organizes visibility rather
   than revoking permissions: active/unsettled work blocks archival, an archived
   workspace cannot dispatch new runs, and saved data/manual edits remain usable.
4. Composer text is scoped/persisted per workspace. Revision fences preserve a
   newer draft when a send fails late; imported IDs cannot collide with old draft
   keys. Clearing falls back to a blank tombstone if removal fails, and explicit
   warnings/retry/in-tab guards apply when all storage writes fail. A forced
   browser termination while storage remains unavailable cannot guarantee a
   durable clear; the product does not promise otherwise.

Import accepts at most 20MiB compressed and 20MiB uncompressed, 2,500 members, and
the existing source/artifact/memory quotas. Two large import-body admissions and
a 30-second upload deadline apply; only the two import routes accept a bounded
28MiB JSON body, while unrelated routes retain 1.6MB. Checks reject unsupported
schema, duplicate/unknown members, traversal, symlink, encryption, digest or
relationship mismatch, malformed/deep JSON and decompression corruption.
Sources are reparsed with the same offline parser: incompatible extraction is
rejected explicitly rather than silently changing the archived text.
