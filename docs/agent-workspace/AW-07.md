## Coherent implementation contract

### 1. Neutral, versioned local source kit

Produce an allowlisted bounded archive with neutral Python core/required fixture
runtime, neutral web source/entry/BFF, locked manifests, local start/verify guide
and source checksums. Do not archive repository root, node_modules, .venv, .env,
private profiles, runtime DBs/backups/corpus, unrelated reports or Git internals.
No whole-project temporary copy. Packaging may use a small owned staging directory
inside the checkout and must remove it; keep one ignored reusable output artifact
only if useful. Archive members must reject symlinks/outside paths and excessive
size/count, and hashes bind actual shipped bytes. Include required font licenses.

This is a **source pilot kit with declared external runtime prerequisites**, not
a self-contained offline binary, clean-machine installer, signed distribution or
commercial redistribution clearance. Reuse already-installed pinned runtimes/cache
for this local proof; no download/install by surprise. Builder proposes exact
launch/installation seam before expanding to bundling dependency trees. Required
mock model/research fixture must exist outside development tests in the kit,
without turning mocks into the production default. Production without an approved
model remains unavailable, never silently simulated. Do not copy/fork UI or loop.

### 2. Offline preflight and explicit runtime lifecycle

Add `workspace preflight` (JSON/text usable offline) and version/build identity.
Check supported Python/Node/pinned direct dependency availability, neutral frontend
build existence, declared-port availability, disk >=10GiB and safe data-directory
state. Tests can inject failures. Missing cache/dependency/build, busy ports,
unsupported/corrupt/newer catalogue give typed code + next action; do not expose
raw exception strings, absolute private paths or environment values in diagnostic
exports. No network/provider test. Avoid breaking existing doctor/launch callers.

One exclusive local ownership lock per data-directory must cover runtime startup,
migration and offline backup/restore. No simultaneous old/new worker against the
same catalogue. Fail busy without killing unrelated processes. Use advisory local
lock, not unsafe PID-only stale-lock deletion. Stop cleans only owned children;
partial startup fails cleanly. Safe environment allowlist unchanged.

Data format/version compatibility is explicit, forward unknown versions fail
before Store migration. Additive migration may initialize metadata for recognized
AW06 schema, after backup or clearly documented offline operator command. Reject
unknown SQL/database structures rather than claiming arbitrary compatibility.
Do not silently fail all pending runs, erase/cancel jobs or drop unknown tables
to make preflight green. Supported upgrade requires drain and reconciliation.

### 3. Offline private backup / new-directory restore

CLI backup acquires exclusive lock and refuses active runs or unsettled effects.
SQLite backup API, integrity checks and a bounded versioned SHA manifest; preserve
required catalogue/DBOS/fixture receipt consistency. Credentials/profile files,
logs and arbitrary children are excluded. Backup remains private0600/parent0700;
if it includes session hashes/audit/application content, state this plainly. It is
not the browser's shareable content export or redacted diagnostic report.

Restore verifies exact known member list, hashes/schema/version and archive bounds
before any destination publication. NEW nonexistent destination only, atomic
staging/rename, no overwrite or broad deletion. No tar/ZIP traversal, symlinks,
duplicate members, bombs, NaN/duplicate-key manifest or forged authority sidecar.
No replay/dispatch during restore. Reject incompatible code/data versions;
rollback means preserve old runtime/data and restore a compatible captured backup,
not replay a new schema through an arbitrary old executable. Document sessions,
unsaved browser drafts, grants/schedules and audit/private backup retention limits.

### 4. First-run / operational UI and safe diagnostics

Extend existing setup panel (no admin dashboard) with local mode/version, safe
health information, a concise first-project guide, simulation limitations and
content-free diagnostics download. Synthetic sample journey may use existing
fixtures and deterministic commands, clearly not natural-language AI.

GET `/api/workspace/diagnostics`, authenticated, JSON allowlist only:
format `agent-workspace-diagnostics-v1`, application/workflow/build identifiers,
simulation/availability state, safe dependency versions, coarse aggregate counts
scoped to current owner, bounded known error codes/recovery hints, checked flags.
No usernames/homepaths/workspace names/IDs/prompts/messages/files/memory/tool args,
session hashes/tokens/provider config/private model strings/URLs/raw exceptions.
No automatic download/upload/telemetry. Redacted structured data only, no logregex
scrubbing as a security guarantee. Browser download explicitly requested locally.
No mutation/backup/restore API exposed to the browser. CLI instructions do not run
shell from chat. UI must also work when no model is configured or API is offline.

Preserve existing white/neutral grayscale/system typography, transcript/composer
as primary, existing rail/minimal details. No forced modal tutorial or extra gate.
Controls have clear labels, keyboard focus/mobile; don't duplicate React keys or
editor IDs. Keep pending async work scoped and unsaved work protected.

### Limitations, cleanup and next boundary

Source kit is **not** a self-contained binary, clean-machine/cross-platform
installation, signed distribution, license clearance or production release.
Hashes verify consistency, not publisher trust. Restore only operator-owned
trusted private backups: recognized table families/minimum columns plus SQLite
integrity are not a sandbox or authentication for arbitrary malicious SQL.
The advisory lock coordinates supported AW07 processes, not an already running
uncooperative older worker. Old AW06 processes must be drained/stopped manually.
Restore preserves captured sessions/permissions and past state; later changes and
browser drafts cannot be recovered from an older backup.

Removed owned root extraction/build/API-recovery scratch, 26MiB retained-contract
pytest scratch, 3MiB isolated E2E catalogue, Builder 28MiB/3MiB test scratch and
reviewer 8.6MiB scratch. Repeated verification reused then removed the same named
scratch; sizes are per captured directory, not an inflated cumulative saving.
Stopped isolated 3130/8130 and 3140/8140/8141/8142 children. Kept one reusable
`.next-build`, the declared 3120 demo and its ignored private backup. No project
copy in /tmp, dependency install, new Next distDir or Docker operation. Final free
disk approximately29GiB; no Docker prune needed because Docker was not used.
