# TIP-026.10 — Completion Report

## STATUS

DONE — implementation and mocked/full-stack verification complete on 2026-08-06.

## OUTCOME

The Ask workspace now uses the previously empty desktop area as a live
`Processing & Evidence Inspector`. The inspector is driven by backend
checkpoints rather than client timers: it shows question understanding,
retrieval, source verification, synthesis and final grounding, followed by a
bounded ledger of authorized source metadata. A cited source opens the existing
Evidence Rail for exact verification.

## DELIVERED

- Added content-negotiated SSE to the existing Ask endpoint. JSON clients keep
  the original contract; web clients request `text/event-stream`.
- Added typed `progress`, `heartbeat`, `result` and safe `error` frames.
- Emitted checkpoints at real AnswerService boundaries. Heartbeats update only
  elapsed time and never invent a pipeline stage.
- Limited streamed source data to marker, record key, display label,
  verification state and freshness state; no snippet, prompt or chain of
  thought is streamed.
- Added a five-stage evidence spine and source ledger in a sticky 360 px right
  column on wide desktop.
- Distinguished sources used in the final answer from sources only checked.
- Wired cited source rows to the current Evidence Rail.
- Removed the legacy 960 px Ask width cap. At the requested 2048 px viewport,
  the workspace uses 1920 px with a 1528 px main surface plus the inspector and
  zero horizontal overflow.
- Added one-column laptop/mobile behavior, reduced-motion handling and full
  VI/EN copy.
- Corrected provider-setup abstention copy so the UI no longer claims that
  evidence was found when a zero-source stream says otherwise.

## SECURITY AND TRUST INVARIANTS

- Candidate metadata is created only after authorization and the existing
  verified/current source filter.
- Stream frames never contain source text, denied identities, provider prompts,
  hidden reasoning or model tokens.
- Final answer/citation persistence, DLP, lineage revalidation and grounding
  checks are unchanged.
- An interrupted or safely refused run leaves the active stage as stopped; the
  client does not paint later stages as completed.

## FRONTEND DESIGN INFLUENCE

The frontend-design skill shaped the result as one restrained evidence spine
rather than a stack of decorative cards. It uses the established achromatic
system, existing typography and a stable desktop information hierarchy while
preserving readable single-column behavior below the wide-screen breakpoint.
