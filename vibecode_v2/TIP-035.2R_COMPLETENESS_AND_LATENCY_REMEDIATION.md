## CONTEXT

TIP-035.2 ran the approved immutable five-case TIP-033 suite once. Four of five
cases passed. `PRD-001` was grounded, cited and relevant but failed the required
term group represented by digest `b2a3048c42f9f0fc`; deterministic reconstruction
maps that digest to the governed application count (“12 trường hợp sử dụng” /
“12 use case”). `PRD-023` passed quality but took 30,053.265 ms, making the
five-case P95 exceed the 25-second release gate.

This remediation is local-only. It does not authorize another external LLM
request, corpus export, embedding operation, connector activation or TIP-034.

## ROOT CAUSE

### PRD-001 completeness

The profile gate certified a facet when at least one evidence marker belonging
to that facet appeared in the answer. That proved provenance participation, not
semantic completeness. A facet containing several material facts could be
reduced to one cited sentence while `coverage_state` still reported `complete`.

### PRD-023 latency tail

Exact definitions already bypassed external query rewriting, but governed
enumerations did not. Even when an exact company identity plus ontology routing
yielded one unique product collection with all members and record bindings, the
pipeline still called the external planner. That round-trip could not add
authority. The TIP-035.2 report does not contain per-stage timings, so it cannot
prove that this was the only source of the 30-second tail; it does prove an
avoidable network stage remained on the request path.

## TASK

1. Add generic, curator-governed material coverage checkpoints to profile
   facets without introducing product-specific branching in runtime code.
2. Activate a checkpoint only when that same facet's authorized evidence
   contains one of its equivalent surfaces.
3. Require both facet citations and all active material checkpoints before
   reporting profile coverage as complete.
4. Give generation and its one bounded repair attempt the exact active coverage
   contract; if repair still misses it, return useful grounded partial content
   with `coverage_state=partial`, never false completeness.
5. Bypass external query rewriting for a deterministic enumeration only when
   the current turn has an exact governed subject and ontology resolves exactly
   one collection for that subject.
6. Keep ACL, DLP, lineage, retrieval, evidence serialization, generation,
   citation verification, collection completeness and persistence unchanged.
7. Run focused, full backend, data-integration, web and mocked-browser local
   regressions before requesting permission for a new external recertification.
