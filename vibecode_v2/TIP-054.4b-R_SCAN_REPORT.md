### R1 single-statement current identity + principal projection

Proposed ownership is Action-local (for example `actions/authority.py`), not
modifying generic identity/context repositories. The query selects actual subject
identity/status/security_version and independently preaggregated memberships;
no roles×groups×scopes Cartesian join. Return a validated Subject plus UUID
principal set from one statement/session.

Preserve all details:

- Roles: active valid_from/expiry predicate, legal Role conversion and existing
  STAFF fallback only when no active roles. Do not invent STAFF's UUID principal
  when no actual staff membership exists.
- Groups: provider labels for Subject.groups versus group UUIDs for ACLs.
- Scopes: all current department/project strings in Subject; add scope UUID
  principals only with the existing exact UUID regexp/cast rules. Preserve
  temporal duplicate rows without duplicate permission effects.
- Principals always include the actor UUID plus actual active role/group/scope
  UUIDs from the SAME projection instant.
- Entitlements: the schema has no valid_from column. Preserve active,
  effect=allow, action/resource/classification conditions and required nonnull
  future expiry; keep `TemporaryEntitlement.active(fresh PolicyContext.now)`
  evaluated at the decision. Do not freeze policy time in the frame or widen
  entitlement semantics.
- Disabled/missing subjects and unknown/ill-typed authority must fail closed.
  Full identity columns must not come from unchecked caller assertions.

A projection is a one-shot phase result, not a request-global cache. A final
lock-owning checkpoint retains its lock query separately. A FOR SHARE statement
can begin before an arbitrarily long wait; statement_timestamp is fixed at
statement start and projections may precede LockRows. Issue a NEW projection
after the LAST relevant blocking actor/capability/template/source/run fence,
not merely after acquiring the first actor lock. Never carry an earlier result
through a provider/storage/native wait, new checkout or transaction boundary.

### Proposed Action-owned functions

```text

    one NEW statement; typed actual Subject + frozenset[UUID] principals
    no FOR SHARE, no permissions retained outside its checkpoint

lock_plan_inputs(session, payload, actor_ids) -> None

```

There is no public frame argument, global ContextVar, session.info or cached

### Single-statement identity/principal SQL shape

Parameters are a typed actor UUID and the existing host UUID regexp; they are
not logged. Each temporal membership is independently projected to prevent
Cartesian multiplicity. Entitlement duplicate rows are retained, and raw JSON
classification type is preserved for Pydantic fail-closed parsing.

```sql
WITH
rm AS (
  SELECT sr.role_id, r.key
  FROM subject_roles sr JOIN roles r USING (role_id)
  WHERE sr.subject_id=:actor AND sr.valid_from<=statement_timestamp()
    AND (sr.expires_at IS NULL OR sr.expires_at>statement_timestamp())
),
gm AS (
  SELECT sg.group_id, g.provider_group_key
  FROM subject_groups sg JOIN groups g USING (group_id)
  WHERE sg.subject_id=:actor AND sg.valid_from<=statement_timestamp()
    AND (sg.expires_at IS NULL OR sg.expires_at>statement_timestamp())
),
sm AS (
  SELECT scope_type, scope_key
  FROM subject_scopes
  WHERE subject_id=:actor AND valid_from<=statement_timestamp()
    AND (expires_at IS NULL OR expires_at>statement_timestamp())
),
em AS (
  SELECT entitlement_id, action, resource_id,
         conditions->'classification' AS classification, expires_at
  FROM entitlements
  WHERE subject_id=:actor AND active AND effect='allow'
    AND expires_at IS NOT NULL AND expires_at>transaction_timestamp()
),
pm AS (
  SELECT CAST(:actor AS uuid) AS id
  UNION SELECT role_id FROM rm
  UNION SELECT group_id FROM gm
  UNION SELECT CAST(scope_key AS uuid) FROM sm WHERE scope_key ~* :uuid_pattern
)
SELECT s.user_id,s.issuer,s.provider_sub,s.email,s.canonical_domain,
       s.display_name,s.status,s.security_version,statement_timestamp() AS checked_at,
       ARRAY(SELECT DISTINCT key FROM rm) AS role_keys,
       ARRAY(SELECT DISTINCT provider_group_key FROM gm) AS group_keys,
       COALESCE((SELECT jsonb_agg(jsonb_build_object(
         'type',scope_type,'key',scope_key)) FROM sm),'[]'::jsonb) AS scopes,
       COALESCE((SELECT jsonb_agg(jsonb_build_object(
         'action',action,'resource_id',resource_id,'classification',classification,
         'expires_at',expires_at) ORDER BY entitlement_id) FROM em),'[]'::jsonb)
         AS entitlements,
       ARRAY(SELECT id FROM pm) AS principal_ids
FROM subjects s WHERE s.user_id=:actor;
```

Build Subject from actual fields using the existing email/domain empty defaults,
SubjectStatus, positive integer security version, Role conversion and STAFF
fallback. Group labels and scope strings remain distinct from ACL UUIDs. No
missing/disabled/invalid row permits authority. SQL.checked_at is observation
metadata, NOT a frozen policy clock; entitlement.active still receives a fresh
PolicyContext.now. This query is read-only; a separate actor lock is retained
where the checkpoint needs it.

Governing stage-one approval retains transaction-time entitlement row selection,
not the initially proposed statement-time filter. This preserves the complete
Subject list even if a grant expires during the transaction; fresh PolicyContext
still makes that expired grant powerless. No outcome-only parity shortcut or
hidden grant widening is assumed.

### Exact leaf batch SQL/policy shape

Reuse the rm/gm/sm/em/pm CTEs INSIDE the leaf statement, never principals passed
from an earlier query. `requested` is host-built from bounded immutable bindings
or independently verified template/record IDs, not arbitrary client SQL.

```sql
WITH requested AS (
  SELECT * FROM unnest(CAST(:ids AS uuid[]),CAST(:types AS text[]),
                      CAST(:actions AS text[])) AS q(id,expected_type,action)
), /* rm,gm,sm,em,pm as above */
leaf AS (
  SELECT q.id,q.action,r.owner_subject_id,r.classification,r.source_zone,
         r.lifecycle_state,r.department_id,r.project_id
  FROM requested q JOIN resources r ON r.resource_id=q.id
  WHERE r.resource_type=q.expected_type
    AND r.resource_type IN ('record','template_version')
)
SELECT l.*,
  EXISTS(SELECT 1 FROM acl_entries a WHERE a.resource_id=l.id AND a.action=l.action
    AND a.principal_id IN(SELECT id FROM pm) AND a.effect='deny'
    AND a.valid_from<=transaction_timestamp()
    AND(a.expires_at IS NULL OR a.expires_at>transaction_timestamp())) AS deny_tx,
  EXISTS(SELECT 1 FROM acl_entries a WHERE a.resource_id=l.id AND a.action=l.action
    AND a.principal_id IN(SELECT id FROM pm) AND a.effect='deny'
    AND a.valid_from<=statement_timestamp()
    AND(a.expires_at IS NULL OR a.expires_at>statement_timestamp())) AS deny_current,
  EXISTS(SELECT 1 FROM acl_entries a WHERE a.resource_id=l.id AND a.action=l.action
    AND a.principal_id IN(SELECT id FROM pm) AND a.effect='allow'
    AND a.valid_from<=transaction_timestamp()
    AND(a.expires_at IS NULL OR a.expires_at>transaction_timestamp())) AS allow_tx,
  EXISTS(SELECT 1 FROM acl_entries a WHERE a.resource_id=l.id AND a.action=l.action
    AND a.principal_id IN(SELECT id FROM pm) AND a.effect='allow'
    AND a.valid_from<=statement_timestamp()
    AND(a.expires_at IS NULL OR a.expires_at>statement_timestamp())) AS allow_current
FROM leaf l;
```

Final SQL will return the actual projected Subject/principals in the SAME
statement alongside these rows, using bounded aggregate/subqueries rather than
an additional identity query. Validate row cardinality/types, classification via
the existing CLASSIFICATION_TO_POLICY, deleted/quarantined rejection, actual
owner/zone/department/project, and exact expected leaf type. Lineage is `[id]`.
`explicit_deny = deny_tx OR deny_current OR (private_context AND nonowner AND
NOT(allow_tx AND allow_current))`. Preserve current owner membership semantics,
ignore no inherited deny, and do not introduce interpretation of ACL conditions
which the baseline does not perform. Exact leaf expected-type drift fails closed.
Generic/nonleaf callers remain on unchanged ResourceRepository inheritance;
they do not receive a fabricated leaf result. This is a SQL shape for approval,
not an executed EXPLAIN or a guaranteed optimal plan.

### Required last-fence checkpoint split

Current `_snapshot` has actor/principal reads BEFORE capability/template/source
FOR SHARE, and standalone `_source_snapshot` principals precede its source locks.
Simply substituting the new query in those locations would be unsafe and is
explicitly rejected. Proposed phases are:

```text
outer domain owner/run/plan/idempotency fence (existing caller)
  → acquire all checkpoint actor/capability/template/current-source locks
  → load existing source/template/context metadata under those held fences
  → NEW single-statement Subject/principal/leaf-ACL checkpoint after last wait
  → synchronous payload/hash/currentness/purpose/PolicyEngine decisions
  → effect/admission/disclosure (no external wait or later lock using that frame)
```

Source and template metadata loaded under held row fences is still checked at
the final checkpoint time for effective/freshness expiry, not an old query clock.
No body is loaded. Capability/source/template rows observed by lock queries are
refetched as metadata for validation; lock-row output itself never authorizes.
Existing source helper APIs need not change for this final-fence split; batching
the separate initial ActionPolicy.sources resolver remains a distinct approval.

Caller completeness (requires explicit Contractor review before product edits):

- Actor admission/submit/R0 receipt/result/R1 source guard: outer run/plan fences
  remain first; retain actor→capability/template→source lock order, then reproject
  the actor after every last wait. Commit/release fences and budgets unchanged.
- Standalone reviewer/source checks: acquire the reviewer actor lock and all
  source locks before new reviewer/principal policy. Do not trust the supplied
  Subject's pre-wait roles/scopes. Origin actor and reviewer frames stay distinct.
- Linked output: origin and requesting viewer are different authorities. All
  known actor/capability/template/source fences must precede BOTH final frames;
  do not revalidate origin after viewer projection and then reuse that viewer
  through the origin's waits. View/render/approve keys cannot collide.
- Multi-actor approval/output checkpoint may require prelocking actor UUIDs in
  a stable deterministic order BEFORE source locks. The present caller order
  can otherwise acquire a second actor after holding source locks. This narrow
  caller-level sequencing change is an explicit design question, not an
  inferred global lock rewrite. Preserve outer run/job owner order and acquire
  no new general ResourceRepository/global/audit locks silently.
- R1 publication performs additional canonical-binding SQL. The final fresh
  authority checkpoint must follow that work too; no frame may cross a later
  binding/source lookup wait merely because `_snapshot` was already called.
