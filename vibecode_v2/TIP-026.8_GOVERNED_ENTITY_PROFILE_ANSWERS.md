# TIP-026.8 — Governed Entity Profile Answers

- Module: Enterprise ontology / Ask planning / grounded synthesis
- Depends on: TIP-024.7, TIP-025, TIP-026.5, TIP-026.7
- Priority: P0
- Date: 2026-08-06
- Status: Completed

## CONTEXT

The live question `HERA là gì?` resolves the correct entity and returns a
grounded answer, but the immutable query plan is `definition/point/direct` and
binds only one definition record. The result is accurate but materially too
shallow for an enterprise product profile even though the authorized SOT has
current evidence for configuration, deployment, ecosystem, applications,
compliance, service and roadmap.

The fix must be domain-general. Pipeline code must not contain HERA-specific
branches or prose. Curators opt an entity into a governed profile by binding
named facets to approved record keys in ontology data.

## ACCEPTANCE CRITERIA

### AC-01 — Generic ontology contract

Given any ontology entity has profile facets, when a definition query resolves
that entity, then its plan is bounded/summary, carries the facet contract and
binds every configured record without a product-name condition in code.

### AC-02 — Retrieval safety

Given a profile record is denied, stale or fails DLP, when profile retrieval
runs, then it is not forced into evidence and cannot be cited.

### AC-03 — Profile completeness

Given all profile evidence is authorized, when synthesis succeeds, then every
configured facet contributes at least one actually used citation. A missing
facet triggers one bounded repair and then honest-null rather than a shallow
answer labelled complete.

### AC-04 — HERA usefulness

`HERA là gì?` covers at minimum: role/use, 1-4-14 and current configurations,
deployment, control/sensing ecosystem, application space, Blue UAS status,
maintenance, warranty and roadmap, with deep citations.

### AC-05 — Regression

Ontology, planning, grounding, backend integration, web rendering and existing
enterprise E2E gates remain green except already documented semantic campaign
failures unrelated to this TIP.

## CONSTRAINTS

- Do not hard-code HERA behavior in planner, retrieval or answer code.
- Do not treat profile bindings as an ACL bypass.
- Do not use legacy/conflicting specifications as current profile evidence.
- Do not weaken citation verification or false-grounding thresholds.
- Do not include price or restricted commercial facts in a general profile
  unless a future governed facet explicitly opts them in.

## DECISIONS LOG

| Decision | Rationale |
|---|---|
| Add an optional profile-facet contract to ontology entities | Scales to products, policies, projects, customers and future domains without code branches |
| Upgrade only opted-in definition queries to bounded synthesis | Preserves concise behavior for entities without a curated profile |
| Require marker coverage per facet | Having evidence in the prompt is not proof the answer used it |
| Reuse definition authority retrieval lane | It already enforces ACL, DLP, lineage and stable reservation before content reaches the LLM |
| Skip a new Blueprint checkpoint | This is a bounded refinement of the approved ontology/query contract explicitly requested by the Homeowner |
