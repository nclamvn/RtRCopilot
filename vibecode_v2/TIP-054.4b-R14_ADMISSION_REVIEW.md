## Admission and cleanup assessment

1. The proposed gate checks exact standard factory/Session/AsyncEngine/asyncpg
   dialect, bounded standard factory options, plain UOW/ActionService/ActionPolicy
   and unoverridden projection method. It requires exact factory object identity
   across execution and authority, not DSN equivalence. It consults only existing
   public engine execution options, exactly READ COMMITTED, before Session/DB work.
   Absent/unknown/custom/overridden/mismatched/RR/serializable/autocommit or extra
   options stay legacy. The actual future predicate still requires code review;
   constructor/type shape alone is not a trust certificate.
2. Source inference is credible: for the supported unmodified SQLAlchemy/asyncpg
   lifecycle, explicit engine options apply before root transaction start and
   produce an explicit RC BEGIN even when server defaults differ. A cached
   dialect.default_isolation_level is only initialization observation and is not
   accepted as that instruction. No current server isolation is claimed verified.
   Arbitrarily hostile engine event hooks/global monkeypatching or mutating
   factory/options mid-request are outside the declared trusted host-code contract,
   not something this predicate can prove safe.
3. Existing RequestConnection plus one read_phase preserves bound engine options
   and accountable task/generation cleanup; no owner rewrite is necessary.
   Actor, row and owner comparison precede receipts; pure DTO materialization is
   after both contexts finish. Actual cancellation/error/checkin evidence is still
   required. A successful response before checkin, detached terminal task or
   fallback after acquisition/query failure is unacceptable.
4. Three means application statements only: actor, one row, bounded receipts.
   Explicit BEGIN, pre-ping, initialization and reset/rollback protocol are real
   operations and must be disclosed separately. No request SHOW or extra probe
   enters counted status. A separate actual SHOW plus delegated asyncpg start
   witness must verify the same configured factory, including reused connections.
5. Read observation remains R13's contract: cancel committed before the row
   statement is visible; after it may not appear. Receipts have their own statement
   observation; this is neither atomic metadata nor latest-at-return authority.
   Source-content/output checks, create/submit two leases and three phases, audit,
   commit uncertainty, nonreplay, budgets and all original thresholds are unchanged.
