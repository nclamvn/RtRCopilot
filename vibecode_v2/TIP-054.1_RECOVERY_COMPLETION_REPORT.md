## Root cause and repair

The original producer committed `render_jobs`, its bindings and publication
outbox, then awaited Redis without handling notification failure. Redis owned
the only dispatch route: the worker polled ingestion's outbox, not persisted
document render work. `process_render` admitted only `pending`; a worker lost
after admission left `rendering` indefinitely. The original final write and
failure/cleanup paths lacked an ownership token.

The repair stays inside existing Document OS / Files / ingestion services:

- Persisted pending render jobs are polled directly before Redis work. A
  notification failure, disappearance or outage cannot own render correctness.
  Producer hint deadline defaults to 1 second; worker queue maintenance and
  blocking pop have absolute 2/7-second guards plus socket bounds.
- Additive migration `0016_document_render_lease` adds attempt, maximum attempts,
  token and expiry to existing `render_jobs`, plus a partial recovery index.
  Admission is atomic under a row lock. The lease is an absolute operation
  budget, default 120 seconds, configured within 10–3600 seconds; it is not
  renewed indefinitely. Attempts default to 3, configured within 1–20 and
  persisted on creation. API status exposes attempt/max_attempts/retryable.
- Expired work becomes `failed / render_lease_expired` and loses its token.
  Unknown staged effects are **not** automatically replayed or deleted.
  An explicit, bounded retry preserves the canonical job and gets fresh
  ownership. Cap exhaustion is a typed 409 `render_retry_exhausted`.
- Publication, failure and cleanup lock/revalidate the live token and expiry.
  An obsolete attempt cannot mutate a newer result. Owned failure cleanup
  only considers that attempt's still-staged objects/quarantined resources.
  Separate attempt-qualified upload names preserve staging lineage.
- Concurrent identical requests serialize both alternative uniqueness keys
  by actor. Existing-result lookup reuses its transaction's row, avoiding
  a nested pool checkout while holding the advisory lock.
- Final guard runs within the publication transaction, with current requester
  authority, template state/rights, locked-fact view rights and exact current
  snapshot checks. Active package/validity checks reuse the bind contract.
  Rendering must also observe actual ingestion rendition `succeeded`, not
  merely assume that a processing call produced a complete staged artifact.

## Issues, deviations and handoff boundaries

- **Known staging debt:** expiry/cancellation/obsolete completion deliberately
  leaves uncertain earlier resources quarantined and unpublished. This TIP
  supplies safety/lineage, not a blind garbage collector. Reconciliation or
  audited, retention-aware staging cleanup is a later explicit task. Ordinary
  owned failures retain the prior scoped cleanup behavior with fencing.
- **Upgrade safety:** drain/stop pre-0016 workers before migration/rebuild.
  Old binaries do not enforce new ownership. Downgrade requires workers drained
  and no in-flight render work. A reversible schema roundtrip does not prove a
  safe mixed-version rolling transition.
- **Lease behavior is explicit:** expiry is failure with bounded manual retry,
  not transparent successful restoration of interrupted Files ingestion.
  Async work has a timeout; synchronous deterministic render code cannot be
  forcibly preempted by an asyncio deadline. Database expiry fences its final
  writes and another/current-returning poller can make its state actionable.
- **Worker health cadence:** worker processing remains sequential; a long
  render can delay the existing Redis heartbeat and other queue work. This
  TIP does not add a scheduler/concurrency framework or certify throughput.
- **No external exactly-once claim:** only internal generated-file publication
  was fault-tested. No real adapter effects, approval/business transactions,
  paid providers, live runtime/SOT mutation or large-scale workload ran.

The conservative expiry policy and additive migration were Contractor-approved
within TIP. Current-identity/fact-rights rechecks are preservation fixes using
existing bind contracts, not new policy rules. Scoped UI work is separate
Builder ownership. Recommendation: Contractor independently rerun the focused
