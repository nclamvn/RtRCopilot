## Design decision — proposal, NOT implementation authorization

Select a **two-physical-lease comparator with three fresh logical transactions**
as the next smallest product experiment:

1. Initial read returns its lease as now.
2. Mutation uses the second lease and the original UOW; actual mutation terminal
   must be acknowledged and transaction-free. All audit/input locks end there.
3. A NEW Session/root transaction performs the same persisted final read/current
   authority using that retained second physical lease, then returns it.

This targets the28 postcommit reacquisition failures without retaining the
initial-read slot throughout the whole request. R4 rejected two leases as the
FIRST probe; R5 three-lease measurements now supply the concrete boundary that
was missing. Changing the ranking is evidence-driven, not an assumed optimization.

Mandatory constraints for a separately approved implementation: never reactivate
old Connection/Session/TX facades by changing tokens; create exact fresh-generation
handles. Prove joined cleanup/repeated cancellation, poison/nonfree fail-closed,
no replay/fallback after mutation, fresh database clock/authority and persisted
results, unchanged idempotency/deadline/budget/audit atomicity. Unknown terminal
or final-read failure remains truthful unknown delivery, not speculative success.

Risks/falsifier: longer second-slot hold can hurt other requests/admission; the
four later-read cancellations and initial/mutation waits may remain. Correctness
proofs must precede a separately approved finite unchanged-oracle ON/OFF comparison.
If caller failures or admission/full16-cell OFF acceptance do not improve, reject
the comparator; no repeated tuning or increase in pool/timeout to force a pass.

Alternatives: no change/OFF is the present safe state; rollback560174 is not a
READY release because its own OFF fails. Broader queue/fair scheduling alters
delivery/wait semantics and requires its own contract including caller wall time.
Audit-chain/authority shortcuts are not justified. Direct ping/cleanup/host
boundary diagnostics remain the alternative if this narrow comparator fails,
not a prerequisite to establishing the observed28-case acquisition boundary.

Under R6: STOP here, no code/test/runtime/load/commit/provider activation. Next
implementation needs Homeowner approval for this bounded design/test scope.
