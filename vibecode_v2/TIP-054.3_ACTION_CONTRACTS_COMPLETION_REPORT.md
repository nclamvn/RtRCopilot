## Implemented contract

Plans freeze server-resolved capability/schema versions, actor/current security
version, private owner workspace or owned context-packet link, purpose,
source versions/checksums, effective policy classifications, resource bindings,
arguments and hashes, destination, DAG, expected outcome and finite budgets.
Changes create new immutable versions/digests; canonical object ordering is
stable. Canonicalization is bounded, type-preserving JSON, not a claim of full
RFC 8785 or semantic equivalence between all numeric representations.
The bounded schema subset rejects unknown or inapplicable keywords;
trusted patterns must be anchored and use full-match semantics, not the entire
JSON Schema specification. Boolean-to-integer coercion and non-finite values
are rejected. Actual HTTP UUID strings and arrays are accepted at the JSON
boundary while authority/implementation/risk fields remain server-owned.

Current identity, effective ACL, source currentness/validity/freshness,
purpose and optional evidence references are checked before disclosure and
again in the final transaction. The final guard uses the same database
session and statement-time denial/principal checks; it never waits on a
nested pool checkout while holding an action run lock.
Only metadata from the shared governed-SOT resolver enters source bindings.
R1 checks the actual approved internal template and existing parameter/fact
binding schema; locked facts become pinned step resources. It does not issue
official/legal documents, render bytes or certify output-class inheritance.

R2/R3 approval binds complete plan digest, exact arguments/amount/destination,
versions/resources/source refs, actor/reviewer security versions and expiry.
Readiness uses the latest decision (created timestamp then approval UUID,
both descending) of one designated currently eligible reviewer. Reviewer
content-view and approve authority plus existing SoD are required; current
reviewer authority, latest approval revocation/expiry and exact binding are
checked after acquiring the run lock. This is CONTRACT_ONLY test semantics,
not a configured production financial/official-document quorum.

Parent budget reservation is internal-only, transactional, monotonic and
idempotent. The initial server ceiling is eight tool calls/120 wall seconds;
unpriced model calls/tokens/spend are inadmissible. No public caller can claim
usage or successful receipts. Events and audit details whitelist IDs, digests,
bounded reasons, numeric reservations and build linkage, not objective,
arguments, recipient or source text. Domain request linkage is a digest of
the public request ID; ordinary HTTP error/header correlation remains intact.
Contract version `rtr-action-contracts-1` is distinct from actual configured
`rtr_build_sha`. This does not claim all global HTTP logs are secret-proof.
