## Exact proposed lifecycle / private interfaces

Ordinary supported operation:

1. Initial read: acquire physical1, logical generation1/new Session/rootTX1;
   original close/checkin JOINED and complete before mutation acquire.
2. Mutation: physical2, generation2/new Session/rootTX2, original UOW. Only
   successful actual commit/context termination AND joined Session close AND
   transaction-free/noninvalidated physical connection permit retention.
3. Retire logical2 completely: clear owner connection/session/factory/generation;
   old facade's immutable token is NEVER changed/reactivated. Keep its connection
   solely as PRIVATE captured physical carrier, no active Session/SQL authority.
4. Final read: verify pending carrier healthy/free, create NEW `_OwnerConnection`
   facade with NEW token using `sync_connection=carrier.sync_connection`; do NOT
   call start/reacquire. NEW factory/Session/rootTX3 reads existing fresh SQL.
   Actual Session.connection MUST return current guarded facade. Then close/
   physical checkin of the shared carrier is JOINED once; all old handles inert.

Initial1 and final logical3 may be read-only rollback contexts; create final uses
its existing explicit begin/commit. All three transaction clocks/TXids independent,
only mutation/final sync binding identical. No old locks survive real commit.
SQL forecast29/2 admission,22/2 submit (excluding ping/wire); not measured gain.
Longer second lease can worsen admission/fairness. Initial acquisition/global
audit/four later-SQL cancellations are not solved by assertion.

Proposed private names/signatures (before implementation):

- `_OwnerConnection.__init__(engine,owner,*,generation,sync_connection=None)`:
  new registered facade, never mutate old token; first/second actual start stays
  the same existing acquisition seam. Bound final start cannot acquire again.
- `read_phase(*,commit=False)` and `mutation_phase()` signatures UNCHANGED.
- `phase_lease(*,retain_on_success=False)`: only mutation passes retention;
  a pending retained carrier is consumed by the next final read, never mutation.
- `has_retained_lease`: read-only infrastructure observation, NOT authority.
- `_retain_phase(connection)`: parent/exact current logical guard first;
  verify joined Session terminal/free carrier, save strong pending carrier and
  revoke logical state. No SQL, permission token or speculative success.
- `_release_retained(error)` / `_close_retained(connection)`: separate internal
  captured-carrier cleanup for the no-active-logical gap. Parent validates exact
  pending target before moving it to a closing-only capture. ONE joined terminal
  Task may base-delegate AsyncConnection.close/invalidate on that capture; old
  public facade methods and release_phase/close_connection still fail before
  delegation/state changes. Never re-enable old logical identity for cleanup.

Root explicitly approved this captured-carrier base-cleanup design. Guard exact
closing capture and parent/registered terminal Task; no child SQL/phase entry.
Clear pending eligibility before starting close, retain closing capture through
joined completion/fault so outer exit cannot double-close/replay. On fault,
poison/cleanup-incomplete remains persistent; no final phase/legacy retry. Primary
ActionError/cancellation survives secondary terminal fault with notes/chain.
Repeated cancel joins the same Task; no orphan terminal Task or new cleanup budget.

Interrupted gap (error/cancel or return before final) outer exit MUST close exact
pending carrier, not skip because phase_active=False. If final-facade construction
fails, captured-carrier release must still run without trusting a missing/new
logical facade. Nonfree/nested/invalidated/closed carrier is never repaired into
eligibility. Generic standalone successive read phases without a mutation remain
the existing independently returned leases; no new public/factory/global pattern.

Expected product edits: helper only; service/execution safe-fallback predicates
