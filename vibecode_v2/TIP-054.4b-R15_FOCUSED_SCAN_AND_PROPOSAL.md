## Source finding and narrow recommendation

Current standard `ExecutionService()` constructs default UnitOfWork then its
ActionService/ActionPolicy against the exact same cached `session_factory()`.
`db/engine.py` constructs one cached runtime AsyncEngine with pool5+5/pre-ping,
then the plain standard sessionmaker with autoflushTrue/expire_on_commitFalse.
It has no explicit isolation option. R14's guarded 3-query status therefore stays
dormant for the standard API service, while its 4-query/3-checkout legacy route
continues. Separately injected policy origins remain possible.

Recommend two small product edits: add a private configuration-only RC view helper
in `db/engine.py`; select that factory only for the exact existing canonical
runtime origin in `actions/execution.py`. Keep original runtime_engine and
session_factory construction bodies, UnitOfWork, write paths and global engine
options unchanged. Status's current joined read phase and pure DTO remain.

The helper would obtain `base.execution_options(isolation_level="READ COMMITTED")`
and a plain sessionmaker bound to that view. It creates no new connection pool,
acquires no connection and issues no isolation probe. SQLAlchemy's exact 2.0.43
source confirms OptionEngine's pool property forwards to the parent and parent
events propagate to the view; disposing a view can replace their shared pool.
Therefore do not dispose the private view or mutate base options.
[SQLAlchemy 2.0.43 engine source](https://raw.githubusercontent.com/sqlalchemy/sqlalchemy/rel_2_0_43/lib/sqlalchemy/engine/base.py).

R14 already established the explicit asyncpg root-BEGIN RC chain and joined
cleanup on real local controls, not new standard-runtime activation. R15 must
prove the same chain on the derived view and actual isolation restoration for
ordinary base-factory transactions. SDK checkin reset sets adapter isolation to
the initialized default: base public options remaining empty alone is not proof
that effective writer isolation is preserved. Cover ordinary transaction isolation
before/status/after (including a non-RC initialized baseline control), while
retaining the declared trusted unmodified host lifecycle. No claim is made for
arbitrary hostile hooks or server/default reconfiguration mid-request.

## Exact admission and provenance proposal

1. Preserve all R14 plain-type/standard-kwargs/same-authority/current-method and
   instance-override checks. Execution, ActionService and ActionPolicy source
   factories must be the exact same object, not merely equal DSNs.
2. Existing admitted explicit-RC plain configurations retain R14 behavior: return
   their original factory unchanged. RR/serializable/autocommit/custom/extra-option
   configurations retain complete legacy before candidate DB work.
3. Only the empty-options standard origin can obtain the new derived factory.
   Check both original session_factory and runtime_engine lru caches are already
   populated before calling them for identity; do not create a default engine
   merely to reject an unknown injected factory. Normal default UnitOfWork has
   populated both caches already.
4. Require source factory `is session_factory()` and its bind
   `is runtime_engine()`, plain AsyncEngine/asyncpg dialect and exact empty base
   execution options. A same-URL replacement, stale cache origin, rebind or custom
   injected empty-options factory cannot obtain a view. Captured standard
   constructors/functions belong to the trusted host implementation, not an
   externally supplied registry/certificate flag.
5. Memoize a private `(base_engine, derived_engine, derived_factory)` configuration
   pair with maximum one base engine entry. Key by exact engine identity. On every
   selection recheck current canonical source and bind, derived exact object/type,
   standard factory kwargs, explicitRC-only options and shared current pool.
   Mutated derived factory/view is rejected, not silently reconstructed/repaired.
   Cache clear or factory/engine cache divergence routes to legacy. A future new
   canonical engine can obtain its own identity-keyed view only after it is itself
   established; no old view is admitted against a new authority origin.
6. Preserve `_status_read_admitted()` as boolean compatibility wrapper over private
   factory selection; status selects once and uses the chosen factory in existing
   RequestConnection. Never assign it into UOW, ActionService or ActionPolicy.
   No permission, Subject, Session, result or transaction is memoized.

Cold-cache, poisoned view and reset behavior are testable boundaries, not presumed
safe because two engines share a pool. No fallback after acquisition/query error
is introduced. Default status behavior changes only when this trusted origin is
fully admitted; a config/object admission failure preserves R14 legacy.
