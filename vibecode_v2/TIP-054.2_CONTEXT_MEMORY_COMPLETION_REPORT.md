## Reused architecture and source contracts

The focused scan reused `PostgresSubjectRepository` and current persisted
roles/memberships, `ResourceRepository.effective_policy_attributes`, existing
effective principals/PolicyEngine, SOT records/current-version/package/
evidence ledgers, `rag.use_class.blocks`, active immutable ontology loading,
and `UnitOfWork`/redacted append-only audit. No new runtime dependency exists.

`SOTReference` pins source key, globally unique record key, exact version UUID,
content SHA-256 and optional server-verified evidence key. Metadata mode
returns no source text and projects only purpose keys from `value_payload`;
it does not load full payloads or relations. Returned source metadata includes
effective PolicyEngine classification vocabulary, SOT zone, owner, source revision, validity/freshness
and retrieval time. Callers such as Actions must revalidate again at their
own admission/disclosure boundary; metadata is not a cached permission.

The content path closes metadata checkouts before fresh revalidation and text
loading, then revalidates the current subject/ACL/purpose/version again. Text
queries use bounded excerpts. Relation annotations are loaded separately only
after source purpose/ACL admission. Both endpoints must have permitted entity
projections, and the relation evidence key must exist on that version. Raw
relation objects are not returned in nested source outputs.

`context_packets` stores only owner/scope/purpose, ontology/query digests,
source refs, entity IDs, memory IDs/revisions, budgets and safe selection
gap/truncation metadata. It stores no source excerpt, note body or query text.
Every read reconstructs the body and rechecks current authority. Original
partial/truncated status survives replay. All-denied context exposes no
candidate names, counts, owners or source identifiers: it returns a generic
unavailable gap. Permitted core facts survive unavailable additional material.

Current schema `records.record_key` is globally UNIQUE. A two-source duplicate
record-key fixture would violate an existing invariant; it was not fabricated
by weakening the schema. Real alias collisions across two ontology identities
are exercised and explicitly labelled ambiguous. Selection also defensively
recognizes a source-key collision if that invariant ever changes.

## API and memory lifecycle decisions

| Route | Contract |
|---|---|
| `POST /resolve` | Read-only bounded context computation |
| `POST /packets` | Reference-only packet persistence |
| `GET /packets/{packet_id}` | Current owner/scope/purpose revalidated reconstruction |
| `POST /memory` | Explicit bounded preference, task note or source-ref inference |
| `GET /memory` | Current admitted private/project/department scope, limit up to 20 |
| `GET /memory/{memory_id}` | Metadata admission before note text, current refs and final revision guard |
| `PATCH /memory/{memory_id}` | Original owner, unchanged scope, current team-write role, optimistic revision |
| `DELETE /memory/{memory_id}` | Owner redaction with optimistic revision; only three-field tombstone returned |

Team reads require current matching project/department membership. Team writes
also require leader/curator. Private access is original-owner bound and needs
no curator approval. An active original owner may safely redact their own note
after team membership is revoked; this exception reveals no note, scope or
source refs. It is not permission to read or correct that note.

Memory is labelled `workspace_memory`, never canonical SOT or permission.
Unknown authority/ACL/capability fields are rejected. Inference requires exact
admitted source refs; if any becomes denied, deleted, expired, superseded or
purpose-incompatible, text and refs are withheld. A concurrent correction or
delete cannot return previously loaded text: the final metadata guard requires
the same active, unexpired revision. Source-compatible notes are still limited
by their declared purpose, not silently promoted into attestation context.

Local ceilings are 2,000 characters/8,000 UTF-8 bytes per note, 20 refs per note,
100 active/unexpired notes per owner, and an absolute initial-creation + 30-day
TTL ceiling enforced by service and SQL. Correction cannot renew beyond that
ceiling and returns typed `422 memory_ttl_invalid` before SQL. Expiry prevents
read disclosure; physical text redaction is the explicit delete operation.
These are local implementation ceilings, not a production retention policy.

Packet selection bounds query/source-key size, duplicates and finite query
counts. The entire serialized packet—including metadata, notes, labels and
gaps—must fit both declared byte and estimated-token budgets. Reduction is
deterministic and labelled truncated/budget-limited. Token counts are explicitly
`utf8_bytes_div4_estimate_not_provider_usage`, not provider usage.

## Issues discovered and resolved

- P1, demonstrated source read boundary: initial integration run was 22 passed,
  1 failed in 44.20s. A newly effective ACL deny removed returned evidence via
  the final check, but text was still selected first. Existing ACL SQL uses
  PostgreSQL transaction-start `now()`; a deny inserted after that metadata
  transaction began had later `valid_from`. The new context path now closes
  that checkout, does fresh current authorization before a fresh text checkout,
  and retains final checks. The zero-source-text-query oracle was not weakened.
  Shared ResourceRepository/policy architecture was not changed.
- P1, demonstrated persistence/audit binding: new memory/packet UUIDs are not
  registered resource IDs, so resource FK audit binding rolled back creation.
  Fixed with `resource_id/type=None` and safe UUID/revision/type details only;
  actor FK and the audit chain remain real. No fabricated resource type added.
- P1, inherited privilege discovery: legacy default grants included UPDATE/
  DELETE on new tables. Migration explicitly revokes packet UPDATE/DELETE/
  TRUNCATE and memory DELETE/TRUNCATE, preserving packet SELECT/INSERT and
  memory SELECT/INSERT/UPDATE. Shared harness verifies actual grants separately.
- Final-boundary hardening: memory revision/lifecycle/expiry recheck, safe
  disappearing-note partial handling and current scope recheck were added with
  concrete race tests. Expiry correction uses the original creation ceiling.

No unresolved failure remains in the owned focused gate. Shared integration,
populated migration/privilege/readiness and broad regression gates remain the
Contractor/Verification Builder handoff, not an assumed result.
