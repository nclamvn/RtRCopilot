# TIP-025.1 — Operational Grounded Evidence Mode

**Date:** 2026-08-04
**Status:** Implemented and verified
**Scope:** Runtime usability without weakening enterprise answer certification

## Problem

TIP-024.6 correctly prevented an unreviewed generative fallback, but made Ask
operationally unusable whenever approved external-processing policy or LLM
credentials were absent. Retrieval could find direct approved evidence while
the end user received no answer.

## Decision

Answering now has two explicitly separated modes:

1. `quality_llm` — preferred synthesis by a configured external generator and
   independent review route.
2. `evidence_only` — deterministic, verbatim extraction from exactly one
   highest-ranked evidence unit that is current and approved/verified.

`evidence_only` is a grounded answer mode, not a generative fallback. It may
reproduce supported evidence with citations but cannot paraphrase, combine
multiple records, infer missing facts or resolve conflicts.

## Trust invariants

- Query intelligence, ACL, DLP, provenance, freshness, relevance and immutable
  lineage checks run before either answer mode.
- Evidence-only output uses one evidence marker and every emitted factual
  sentence carries that marker.
- Claim-tier, stale, empty or unapproved evidence cannot be emitted.
- Missing evidence still produces honest-null and a governed knowledge gap.
- Missing LLM configuration never creates a false knowledge gap.
- Enterprise answer evaluation and release certification treat
  `evidence_only` as **not quality-configured**; it cannot satisfy the LLM
  answer-quality gate.
- The client displays the actual mode and never labels evidence-only output as
  LLM synthesis.

## Acceptance criteria

1. With no LLM credential, “Hera là gì?” returns a grounded answer citing
   `HC-001` when that record is authorized, current and approved.
2. With no LLM credential, “Vega là gì?” returns a grounded answer citing
   `HC-002` and does not create or increment a knowledge gap.
3. The response contains `answer_mode=evidence_only`; the UI labels it as a
   verbatim SOT extraction with no inference.
4. Unknown entities, irrelevant evidence and ambiguous queries continue to
   fail closed.
5. Enterprise domain-stratified evaluation remains incomplete for answer cases
   until an approved quality LLM path is configured.
6. When the approved LLM route is ready, runtime prefers `quality_llm` without
   changing retrieval or trust gates.

## Supersession boundary

This TIP supersedes only TIP-024.6 requirements that made missing credentials
disable all runtime answers. It does not relax the no-hallucination rules,
external-processing policy, independent LLM review or TIP-025 release gates.
