## CONTEXT

Quality remains the non-negotiable release gate, but the previous validation
cycle spent provider credit inefficiently. The local audit trail for the last
seven days contains 402 answer runs and 776 metered provider-call units: 568
answer-generation/review units, 187 query-rewrite units and 21 legacy units.
One TIP-026 hour alone created 73 answer runs. Code editing itself did not spend
the credit; repeated live planner, generator, reviewer and repair calls did.

The historical `answer_runs.input_tokens/output_tokens` fields were partially
estimated from text size and therefore cannot be treated as a provider invoice.
The architecture must record provider-reported usage, prevent accidental full
campaigns and remove calls that add no release-quality signal.

## TASK

Implement a provider-neutral cost-governance layer that reduces redundant work
without weakening ontology resolution, ACL/DLP, evidence selection, citation,
entity, relevance, collection or profile gates.

## DECISIONS LOG

| ID | Decision | Rationale |
|---|---|---|
| D-0275-01 | Exact, governed entity definitions and explicit point attributes bypass the external query planner | Ontology already resolves these requests deterministically; an LLM adds cost but no new semantic information |
| D-0275-02 | Ambiguous, fuzzy, contextual, comparative, procedural and broad questions retain LLM planning | Cost reduction must not weaken ordinary-language understanding |
| D-0275-03 | Point/direct answers skip the advisory LLM reviewer but retain every deterministic grounding gate | Reviewer does not own final acceptance and previously produced false-negative vetoes |
| D-0275-04 | An advisory review rejection is recorded but never triggers a second full generation by itself | Repeating an expensive generation for a non-authoritative signal is waste |
| D-0275-05 | Deterministic grounding failures retain one bounded repair attempt | This repair can materially improve citation completeness and therefore remains quality-bearing |
| D-0275-06 | Provider response usage is the accounting source; no embedded price table | Token/caching facts are durable, while provider prices change independently |
| D-0275-07 | Calls and tokens have independent subject/global daily ceilings | Calls stop retry/fallback loops; tokens stop large prompt/reasoning spend |
| D-0275-08 | Prompt cache keys are stable and contain no question, user or evidence text | Improve provider cache locality without leaking identifiers |
| D-0275-09 | Enterprise E2E defaults to a bounded 12-case smoke slice; full campaign requires `E2E_APPROVE_FULL=1` | Routine QA must not silently run 77+ live cases |
| D-0275-10 | Governed authority records have a separate 20-record ceiling while ordinary retrieval remains at 12 | A profile/list contract must not silently lose a required record merely because its authority set is larger than the generic prompt budget |
| D-0275-11 | Normalize citations, then prune every remaining uncited unit before re-running all deterministic gates | Keep the grounded subset useful without accepting, inventing or auto-citing unsupported prose; avoid a second LLM generation for presentation-only defects |

## SPECIFICATIONS

1. Normalize OpenAI and Anthropic usage into calls, input, cached input, output,
   reasoning and total token fields.
2. Keep usage request-local under concurrent async traffic.
3. Persist combined rewrite and answer usage with the grounded answer audit.
4. Export Prometheus counters for all usage dimensions.
5. Enforce registry-configured daily call and token budgets before admitting a
   new provider phase; debit actual usage after a completed response.
6. Cache query-plan results by ontology digest plus full planner input with a
   bounded TTL and entry count.
7. Right-size output ceilings by answer contract: point lookup, definition,
   entity profile and full list/analysis remain distinct.
8. Use a low-reasoning, 256-token reviewer route where review remains useful.
9. Preserve provider fallback for genuine transport/generation failure.
10. Never run external live acceptance while provider credit is unavailable.

## ACCEPTANCE CRITERIA

- **AC-01:** Exact governed definition/point questions require no external
  planner call and still resolve the correct canonical entity.
- **AC-02:** Fuzzy/contextual questions still use the LLM planner.
- **AC-03:** Point/direct answers require one synthesis call, not an additional
  advisory review call.
- **AC-04:** Broad answers keep deterministic verification and a bounded repair
  path; no safety or evidence gate is removed.
- **AC-05:** OpenAI and Anthropic response usage is parsed and aggregated per
  request without cross-request leakage.
- **AC-06:** Subject/global call and token budgets are independent and auditable.
- **AC-07:** Identical planner input under the same ontology digest uses cache;
  ontology drift invalidates the cache key.
- **AC-08:** Routine enterprise E2E is bounded; full provider-spend execution is
  explicit.
- **AC-09:** Full backend, Ruff and mypy regression suites pass.
- **AC-10:** The bounded live HTTP and browser campaign passes with zero
  false-grounded answers; the complete 77+ campaign remains an explicit,
  separately approved release exercise.

## CONSTRAINTS

- No weaker model is introduced for answer generation merely to reduce price.
- No answer may bypass authorization, DLP, provenance or grounding checks.
- No hard-coded currency price is used for billing decisions.
- No credential or provider payload plaintext is written to audit logs.
- Existing dirty workspace changes are preserved; this TIP does not commit or
  push them.
