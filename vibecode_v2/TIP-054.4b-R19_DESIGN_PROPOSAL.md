# R19 finite OFF qualification design

2026-10-09 · Builder proposal · Vibecode Kit v6.2.
Implements the accepted Main TIP without product, helper or R18 byte changes.

## Minimal packet

New R19 files only: finite `contract.json`, `qualification.py` (source/raw gate),
`bounded.py` (narrow R18-pattern supervisor adaptation),
`test_r19_offline.py` (exact six grouped controls) and a pre/HTTP shell wrapper.
No rewritten workload driver, successful service stub, phase/PG observer, extra
campaign, native stage or new dependency. Freeze a new source epoch and accepted
review hash before Main's separate pre/HTTP admissions. Preserve failed epochs.

Bind the current full 204 product / 192 test inventories using R18's documented
sorted SHA/path recipe and expected digests. Bind R18's 665 source pins, 385 raw
seal, final Verify/closure and original OFF helpers; bind R19 source/design/TIP.
Host source checks remain host-only. Container sources use `/work`, backend
`/workspace`, and raw evidence `/evidence`; do not assume repository docs mounted.
Source packet <= 1 MiB, contract <= 64 KiB, pre evidence <= 10 MiB.

## Admission and one-shot flow

Main `pre`: same-binding source/fixture checks, compile/scoped Ruff/format/pins,
exact six-control collection/execution/XML, zero failures/errors/skips. Every
pytest invocation explicitly uses existing backend config/root. No product
regressions are re-executed or inherited as fresh R19 tests.

Main `http`: only fixed fresh `http_e1`, accepted source review and passing same-
binding pre. Check unchanged four IDs/images/mounts/caps/ports/internal network,
running/unpaused/no restart/OOM and idle runner. Install fail-closed cleanup before
CREATE; require both exact DB names absent and host >= 20 GiB / PG >= 524,288 KiB
before each CREATE. Track only acknowledged task-owned creations; migrate domain
to `0019_action_executor`, use existing separate engine role for empty engine DB.
Verify role premises read-only; fail before launch if they do not hold. No shared
ALTER ROLE or engine SDK/bootstrap. Unknown CREATE outcome is retained/reported,
not guessed as ownership.

Immediately before spawning the original OFF command, exclusively create a
persistent one-use launch marker with reviewed binding/contract hashes and fixed
`http_e1`. Existing marker/HTTP evidence or uncertain launch denies continuation;
no `http_e2`, marker deletion, retry or automatic repair launch. Resource setup
failure known to precede the marker is labelled unlaunched/allowance unused, but
its evidence is retained and does not authorize reusing/overwriting that epoch.

Launch the unchanged baseline in `off` mode in a clean synthetic environment.
Only this process enables queue submission with isolated domain/engine DSNs;
serving default remains OFF. Offline providers, no worker/native effect process.
Minimal PYTHONPATH must not accidentally import experiment observers. Keep seed
and request behavior unchanged; owned evidence TMPDIR avoids persistent scratch.

## Timing and termination

The entire child, including imports/control creation/seeding, has 190 seconds.
Exactly one absolute 10-second cleanup deadline is shared by all TERM/KILL/drain
and reap paths; no second grace after failure. Static/migration children have
120-second execution budgets and the same single 10-second cleanup contract.
These are per child, not whole-stage bounds or real-time OS guarantees.

The in-container supervisor owns a fresh group and inherited unique token.
Validate ownership before signals; foreign/unknown group members fail closed.
Host interruption asks that supervisor to stop, joins exec, proves matching
drained owner/result before clearing ownership or dropping DBs. Every stop/proof
failure explicitly returns nonzero even in Bash conditional-errexit contexts.
Still-active means STOP. Keep complete stdout/stderr/process/closure records.

Campaign cap is 10 MiB over its declared epoch, including logs/journal/final JSON
and closure outputs. Polling may overshoot; detected excess retains all bytes and
fails, never truncates or certifies a hard quota. After proven drain, drop only
owned engine/domain DBs and prove exact catalog absence; unresolved cleanup holds
resources for Main. Finish source/fixture/idle/capacity/raw seals on failure too.

## Independent raw reconstruction

Freeze 1,600 keys: profiles 1/10/25/50 × cases 0..99 × four operations. Require
unique bounded typed rows, finite nonnegative timing, original HTTP-status/okay
agreement and expected successful states. Compare parsed journal and final JSON
in exact list order; do not sort them into false equality or repair torn bytes.
Check per-case operation chronology and sequential profile blocks, not a global
completion order across concurrent cases. Status failure does not imply missing
cancel; observed admission/submit failure cannot license later observations.

Reconstruct all 16 cells independently from raw values, including failed timings:
count, failures, missing IDs and nearest-rank p50/p95/p99. PASS needs 100 samples,
zero errors/missing, p95 <= 500 ms admission / <= 1,000 ms otherwise, complete
unchanged-helper summary/verdict, helper exit zero and proven resource/source
closure. Oracle/driver abort is integrity failure even with successful-looking
HTTP records. Absent/partial final artifacts and JSONL divergence remain failure,
not fabricated call starts, server outcomes or repaired latency.

Original normal timer ends before decode/flush; exception timer differs. Raw DTO
fields not recorded stay unmeasured; original body assertions and process outcome
are separate proof. No percentile subtraction, observer-cost correction, tuning,
warm-up workload or R17 M substitution. Analyzer runs after any campaign outcome;
original child code stays retained and a parser error cannot erase its packet.

## Six proposed offline groups and decision state

1. Frozen contract/source/one-use admission rejection.
2. Raw schema, exact identities, duplicates and torn-journal rejection.
3. Nearest-rank cell/error/missing conservation and original thresholds.
4. Oracle abort, state validity and original summary/JSON agreement.
5. Owned process deadline/cap/shared-grace and conditional-shell fault controls.
6. Fixture/DB ownership cleanup and honest observer/executor/readiness ledger.

Host controls use synthetic files/short-lived owned processes only, no product
import, SQL or HTTP. Actual test names/counts and source hashes are frozen during
authoring. Main/independent review own runtime and actual result proof.

Main accepted these DB names and the fixed `http_e1` marker contract; independent
Reviewer accepted TIP/design authoring with no P0/P1. If source work exposes a
new scope choice, stop and ask Main. Successful HTTP qualification can close only
EXE-009 after all six HTTP requirements are accepted; broad/static/package/
migration/native/restore and `.5` remain separate. Failure selects one evidence-
backed next decision with no repeat campaign.
