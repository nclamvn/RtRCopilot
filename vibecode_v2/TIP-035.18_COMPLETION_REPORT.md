## Outcome

The production configuration gate is no longer a thin Pydantic boot check. It
now has one explicit contract and three fail-closed layers:

1. a content-free host validator for exact build binding, OIDC/domain policy,
   secret separation, provider policy, connector-off state, ingress coherence
   and real TLS material;
2. Compose materialization from the same fully resolved env file;
3. application `Settings` construction inside the locked backend image.

The real `.env.production` is explicitly ignored. The tracked template
contains only unmistakable placeholders, and `make production-config-init`
creates a mode-600 copy without overwriting an existing operator profile.

## Security closure

The validator never sources the env file and rejects `${...}` or `$(...)`
expressions. Its report contains stable error codes, booleans, counts and
digests only. It does not contain domains, secret values, DSNs, certificate
paths or credential-source values.

Production now fails closed on:

- a dirty, development or mismatched build identity;
- reserved/mismatched public, ingress or OIDC origins;
- empty corporate domain policy or malformed group mapping;
- known placeholders, short/reused secrets and owner/runtime DSN mismatch;
- an external answer/embedding configuration without the approved `internal`
  policy and a real provider credential;
- active enterprise connector configuration;
- local/self-signed TLS mode, invalid/expiring/mismatched certificate material,
  broad private-key/env permissions or HSTS below one year.
