## Exact environment contract

The outer contract requires nonempty string values for both
`POSTGRES_DSN` and `INTEGRATION_DATABASE_DSN`, byte-equal to the explicitly
declared owned domain DSN. Validate canonical PostgreSQL scheme, synthetic
`rtr_app` identity, fixed `tip054-pg:5432`, fixed synthetic credentials and the
exact admitted database. Reject missing/empty, mismatched, whitespace/encoded
aliases, foreign database/identity/host/port, query/fragment and unsafe values
before subprocess spawn, CREATE or any future marker operation. Do not silently
fill, normalize or repair missing integration configuration.

The reusable pure validator accepts an explicitly declared domain contract; it
does not authorize future databases/campaigns. R20 freezes only
`rtr_tip054_r20_local_e1`. The seed-only envelope keeps executor false, no
workflow DSN, providers offline/local, timeout 0.9 s and unchanged default quotas
30 render / 120 default-read over 60 seconds, not HTTP campaign quotas 5,000. Future
queueing/enabled envelopes require their own admission.

## Meaningful runtime proof

The read-only negative process is a separately admitted diagnostic, not an
invalid bootstrap envelope. Its outer admission is valid; inside that fresh
child, intentionally omit integration immediately before importing the original
baseline helper. Assert captured global empty and original `synthetic_settings`
raises the expected postgres-DSN ValidationError despite valid POSTGRES_DSN.
Call no principal, engine creation/connection, migration, publication or SQL.
Pure negative mappings separately prove no spawn/CREATE/marker callback occurs.

The positive process validates the envelope before helper imports, then asserts
the captured baseline and context integration globals and actual synthetic
Settings DSN equal the declared domain. Inspect canonical runtime pool 5+5/
pre-ping and settings/quotas/timeout without a warm-up. Per Main's design choice,
the positive probe uses unchanged `session_factory()` / `runtime_engine()`
directly, not a custom or tuned seed pool. The original latency helper's separate
seed engine remains unchanged; R20 is a seed-only closure, not driver equivalence
or a latency comparator. Assert actual offline providers, empty external API keys
and executor false in both the declared runtime and original synthetic Settings.

Create two distinct principals with the original admin/owner roles, call the
same original `publish` with the unchanged UUID source/reference-generation
formula and fixture timestamps, then the same `ActionService.admit_capability`
for `sot.read` version `2`. No successful service/factory stubs or patched
module globals. Assert current persisted principals/roles, nonempty returned
reference(s), exact current record/version/hash linkage, active owned resource
and owner view ACL, persisted admitted capability/digests/admitted-by admin,
the admission audit, expected pending reindex outbox with no dispatcher, and zero
action plans/runs/executions. Dispose the created canonical engine in finally.
Retain a bounded assertion summary, not latency samples or secret DSNs.

## Resource sequence and retention

Only Main executes: source/review/environment/fixture admission → static/exact
six controls and read-only negative → initially absent fresh domain → per-CREATE
host >= 20 GiB and PG >= 524,288 KiB guards → acknowledge task-owned CREATE →
domain migration 0019/owned grants, no shared ALTER ROLE → one positive seed
probe → exact owner-matching child drain → DROP only acknowledged owned domain →
fresh catalog absence/source/fixture/idle/capacity closure.

All TMPDIR, pytest basetemp and explicit publish/staging roots stay beneath the
owned evidence directory; do not use the product's default `/tmp` staging paths.

Reuse `/work/r19/bounded.py` directly with `stage=pre` at the NEW sibling
`/evidence/r19/r20_bootstrap_e1`. Labels never `load`; every child gets
120 seconds, one persisted absolute 10-second cleanup deadline and existing
10 MiB polled cap. Do not call the R19 campaign wrapper or marker API.
Invoke the original supervisor path directly so its `qualification` import
resolves the pinned R19 module; do not introduce a conflicting module name,
patch its globals or substitute caps. Preserve original owner/deadline semantics.
Unknown ownership/CREATE/stop/proof outcome fails closed and retains resources.
No output truncation, forced foreign cleanup, Redis FLUSH, install/build or image
replacement. Early traps and explicit failure returns precede CREATE.

The binding covers unchanged full 204-product/192-test inventories, all declared
R19 source/raw/history/consumed marker and its final Verify/review, required
unchanged helpers and new R20 inputs. New R20 evidence is the only allowed
addition under the supervisor's R19 raw prefix; original epochs remain untouched.
Source packet <= 1 MiB, manifest <= 64 KiB; Main final raw seal covers new results.
Preserve before/after hashes, actual failure records and owned cleanup. Main owns
Docker hygiene/prune; no volume/container deletion.
