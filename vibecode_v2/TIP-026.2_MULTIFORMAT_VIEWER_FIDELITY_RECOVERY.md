# TIP-026.2 — Multiformat Viewer Fidelity Recovery

**Priority:** P0 product usability and document-trust recovery
**Depends on:** TIP-008, TIP-024.5, TIP-026.1
**Working directory:** `/Users/os/RtR/KnowledgeBase/RtR_Copilot`
**Status:** COMPLETE — verified 2026-08-05

## Context

The Files workspace currently shows an approved PPTX through a generated PDF,
but the generated artifact is not an Office rendering. The ingestion pipeline
extracts every text run, discards slide geometry and images, then writes a
linear A4 PDF with ReportLab's default Helvetica font. The affected source has
22 slides and uses Be Vietnam Pro; its generated preview has only 15 pages,
loses the original composition and maps Vietnamese glyphs to incorrect symbols.

The UI then compounds the problem by reserving a permanent 280 px inner tools
column inside an already three-column workspace. A decorative `locator-spine`
is absolutely positioned over that tools column, producing the vertical stack
of empty square-like marks visible in the reported screenshot. It is not a
thumbnail strip and does not expose an interaction.

## Product intent

The viewer is an enterprise evidence workstation. Its dominant object is the
file itself; navigation, search and provenance are instruments around that
object. The visual language remains monochrome and restrained. Every visible
control must communicate a real capability.

## Task

1. Replace lossy DOCX/PPTX text-to-PDF previews with sandboxed, headless Office
   conversion that preserves page/slide geometry and embeds or substitutes a
   Vietnamese-capable font deterministically.
2. Preserve structured native extraction for search, locators and evidence.
3. Replace the decorative locator rail with a compact semantic page/slide
   indicator and a responsive command bar.
4. Give the canvas the available width; expose in-file search without a
   permanently open nested sidebar.
5. Audit image, PDF, DOCX, PPTX, XLSX, video and audio viewers at desktop,
   tablet and mobile widths.
6. Regenerate the affected existing Office rendition after the corrected
   pipeline is deployed.

## Acceptance criteria

- **AC-01 — Vietnamese fidelity:** Generated Office PDFs preserve the strings
  `Đà Nẵng`, `lãnh đạo`, `năng lực` and contain no `.notdef` replacement caused
  by the preview generator.
- **AC-02 — Layout fidelity:** A PPTX with 22 slides produces a 22-page PDF with
  the source slide aspect ratio; DOCX pagination comes from the Office renderer,
  not a flattened A4 text stream.
- **AC-03 — Safe conversion:** Office conversion runs as the non-root worker,
  with bounded time/output, no shell, no external network I/O and an isolated
  writable user profile. Local process IPC remains available to LibreOffice.
- **AC-04 — Semantic continuity:** Structured JSON extraction and in-file
  search remain available and retain page/slide/cell/time locators.
- **AC-05 — Meaningful controls:** The decorative vertical locator spine is
  absent. PDF and Office surfaces expose a compact page/slide position,
  previous/next controls and a labeled search toggle.
- **AC-06 — Responsive balance:** No horizontal page overflow or overlapping
  controls at 360×800, 768×1024, 1024×768 and 1440×900. The document canvas is
  the dominant region at desktop and tablet widths.
- **AC-07 — Format matrix:** Image, PDF, DOCX, PPTX, XLSX, video and audio use
  only authorized safe renditions and each renders its primary content and
  search/locator state without regression.
- **AC-08 — Existing artifact recovery:** The reported
  `RtR_DaNang_UAV_Briefing.pptx` preview is regenerated and visually/textually
  verified against the source.
- **AC-09 — Quality gates:** Backend unit/integration, web unit/browser,
  accessibility, Ruff, mypy, ESLint, TypeScript and production build pass in
  proportion to the change.

## Constraints

- Do not render or serve the original Office file directly in the browser.
- Do not weaken authorization, rendition filtering, range requests, download
  policy or provenance.
- Do not use a cloud conversion service for internal files.
- Do not mutate the original object or its checksum.
- Preserve all uncommitted TIP-026 and TIP-026.1 work.

## Decisions log

- Vibecode sequence: SCAN → TIP → BUILD → VERIFY → Completion Report.
- High-fidelity Office conversion uses LibreOffice headless mode inside the
  existing process sandbox. Structured extraction remains Python-native and is
  not replaced by PDF text extraction.
- Be Vietnam Pro regular, bold, italic and bold-italic are installed from a
  commit-pinned Google Fonts source with checksums. Liberation and DejaVu remain
  deterministic fallbacks for other common Office fonts.
- The frontend uses one compact command bar above the canvas. Search is a
  collapsible tool drawer, not a permanently reserved fourth visual column.
