## Decision

Select **transaction-scoped physical leases, three phases**, as the next narrow
controlled remediation candidate. Release the connection after the initial
transaction; acquire a fresh lease for mutation, commit/rollback it genuinely
before checkin; acquire another fresh lease for the persisted final read.
Preserve the current Task/session/facade isolation, real fresh authority,
idempotency/once-only fallback, maintenance/input/evidence/audit order and
truthful postcommit failure handling. This is not restoring old source bytes or
removing R3 safety controls. Three checkouts are acceptable if total occupation
and caller latency improve; checkout count is no longer the optimization goal.

This is an **evidence-supported experiment selection**, not a measured fix or
promise to meet500ms. Source mechanics plus observed pool occupancy/endpoint
association justify this smallest reversible comparison. Serial instrumented
runs do not prove that coalescing caused the entire regression, and historical
three-checkout e6 still failed the50-admission SLA. A fresh unchanged OFF gate
must decide acceptance. Implementation needs a separately approved R5 packet:
the user authorized investigation/design selection here, not this changed
physical-lease/test-count contract.

## Options and why this one

1. **Three transaction-scoped physical leases — SELECTED first.** Exact
   scheduling boundaries align with actual transaction/authority boundaries;
   strongest comparison with the preserved e6 lifecycle, while retaining current
   safeguards. Forecast29/22 SQL and3 checkouts, not a latency forecast.
2. Two leases (initial separate, mutation+final shared) — defer. May reduce
   reacquisition, but still spans commit/final-read ownership and introduces a
   second confounding choice before the three-phase hypothesis is tested.
3. Bounded pre-acquire Action scheduling — defer to a separate contract. Could
   preserve pool capacity for status/cancel, but adds fairness/overload/cancel
   semantics and cannot guarantee multiworker fairness from one asyncio gate.
   Never move waiting outside measurement or reset the0.9s execution timer.
4. Audit chain sharding/detaching/head caching or skipping fresh permission
   checks — reject. Changes safety/atomicity rather than fixing measured work.
   SQL/lock batching is also not selected without separate semantic proof.
5. Keep current code unchanged — correct state for this diagnosis turn, but
   not a solution or permission to activate the failed candidate.

## Proposed R5 implementation/verification contract — not yet authorized

Private Action lifecycle only; no shared pool/UOW/audit/schema/API/DTO or
dependency change. Each phase's guarded connection/session must be physically
closed before another phase can acquire; stale handles must be rejected before
SQL, including across physical generations. Keep one request-local Task and
mutation-started/outcome state across all phases, never a permission/result
cache. Close only after real transaction exit, using existing joined cancellation
cleanup. No new acquisition until uncertain commit cleanup has completed; never
replay after mutation starts. Unsupported/clock/R1/legacy complete fallback still
occurs once with no live borrowed connection. Final disclosure uses a NEW
persisted read after real commit, even if reacquisition times out.

Risks: additional queue/pre-ping cost, final-read timeout after durable commit,
child/stale facade leaks during connection-generation changes, reordered locks,
duplicate/reset on fallback. Finite controls must cover all of these. Rollback
is reverting only the separately approved lifecycle patch to frozen560174;
no destructive reset or silent code/data migration. Executor stays default OFF.

Regression epoch must be explicit BEFORE edits: retain all356 active cases
(290 SQL +66 pure); archive current observation/count assertions and change
only approved physical-count/lifetime expectations. Preserve all business,
permission/expiry/clock/grant/duplicate/deadline/audit/commit assertions; no skips,
xfails or removed failures. Add real physical-generation isolation and return
proofs. A1-checkout assertion must not simply be disabled or portrayed unchanged.

Use a new isolated synthetic fixture with identical pins/caps/pool5+5/pre-ping/
quotas and helpers, no serving/private data/provider. Freeze and measure current
baseline first; close it before implementation. After focused correctness,
static/import and independent critical proofs, measure new lease counts/intervals
then run exactly the unchanged OFF1/10/25/50×100 oracle. Reacquisition/scheduler
waiting stays inside HTTP timing and the existing execution timeout. Keep all
failed trials; no retry-until-green. OFF FAIL stops further tuning/broad proof;
OFF PASS alone permits whole-current backend/native/migration/restore/wheel gates.
