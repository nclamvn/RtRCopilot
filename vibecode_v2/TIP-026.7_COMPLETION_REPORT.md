# TIP-026.7 — Completion Report

## Outcome

The Ask pipeline and its release-test path are now consolidated into one
repeatable workflow. The implementation is complete, but the enterprise
semantic acceptance gate is deliberately **not marked complete**: the first
full live campaign exposed material retrieval and grounding defects that unit
and mocked E2E tests did not reveal.

## Delivered

- Added bounded conversation-aware query planning with a self-contained
  retrieval question. History is owner-checked, limited to four messages and
  600 characters, and inspected by DLP before external processing.
- Preserved the current user question as the authority and stored only bounded
  planning digests/counts in audit metadata.
- Made LLM usage accounting request-scoped so concurrent requests cannot debit
  one another's call budgets.
- Split transport/provider failures from deterministic quality rejection.
  Transport failures stop promptly; an evidence-grounding rejection permits
  one bounded repair call.
- Preserved pre-retrieval DLP findings after retrieval resets trace state.
- Added a 77-turn, domain-stratified HTTP acceptance campaign covering company,
  product, operations, systems, methods, safety and multi-turn conversation.
- Added real, unmocked Playwright journeys for colloquial company identity,
  pronoun follow-up, exhaustive governed collections and unknown-entity
  abstention.
- Added `make e2e-enterprise` and an isolated runner that clones PostgreSQL,
  uses Redis DB 15, binds temporary services to loopback, checks source-ledger
  isolation and removes exact temporary resources.
- Made the runner execute browser E2E even when semantic acceptance fails, so
  one failed gate cannot hide results from later gates.
- Corrected the acceptance oracle for harmless number/date formatting while
  retaining strict citation allowlists, required concepts and zero tolerance
  for false grounding.
- Ignored generated `latest_*.json` reports so execution artifacts do not
  enter source control.

## Acceptance outcome

| Area | Result |
|---|---:|
| Implementation and regression gates | PASS |
| Isolated infrastructure and cleanup | PASS |
| Live browser journeys | 4/4 PASS |
| Enterprise HTTP semantic campaign | 54/77 PASS |
| Release verdict | **NOT READY for unrestricted enterprise pilot** |

The Vibecode method changed the outcome materially: the campaign was treated
as an independent acceptance contract rather than as a demonstration script.
No threshold was relaxed and no failing domain was hidden behind the aggregate
unit-test count.

## Remaining product defects

1. Broad and cross-domain questions still lose relevant evidence or abstain
   after evidence is found.
2. Entity-name collisions in the systems corpus can produce supported but
   wrong-entity answers.
3. Conversation anchors and pronoun resolution are implemented, but only 40%
   of the current follow-up cases satisfy the complete citation/meaning oracle.
4. Methods and systems are the weakest corpus strata and require retrieval and
   ontology repair before general pilot claims.
5. Eight answers were grounded to evidence outside their approved oracle group;
   these are release blockers, not cosmetic scoring differences.
