## Deliverable

Typed versioned capability registry, immutable plan/admission/approval domain,
redacted events/receipts and transactional bounded run-budget accounting,
exposed through authenticated API where appropriate. This is an actual local
domain lifecycle, not a claim that actions are executable yet.

Registry is host-controlled and administrator-admitted (manage_policies);
clients/models cannot choose arbitrary implementation names, SQL, HTTP URLs
or downgrade effect. Start fixed reviewed internal capability contracts for
`sot.read` (R0/view) and `documents.create_draft` (R1/render, internal only),
not dynamic executable loading. R2/R3 are typed and validated in synthetic
contracts but remain unavailable for dispatch. SDK/runtime/MCP later.
Versions/digests/input/output schemas/effect/policy/limits/implementation ref
immutable once admitted; changes create a new version. Strict bounded schema
subset supported explicitly: unsupported constraints fail closed; no pretending
a partial validator implements full JSON Schema. JSON canonicalization rejects
non-finite values, unsupported values and mutable authority metadata.

ActionPlan freezes actor/scope/objective/purpose/capability versions/schema
digests/resource and source refs/argument hashes/destinations/dependencies/
effect/finite budgets/expected outcome. Server resolves registry/resource
attributes and current source revisions; a client's supplied digest is never
trusted. Version/input/recipient/amount/source change changes server digest
and invalidates authorization. Dependency cycles/unknown names/additional
fields and expansion beyond host limits fail before admission.

Current subject must be reloaded; resource authority/purpose/currentness is
checked before context content and before marking admitted/ready. Coordinate
with Context Builder for a shared source-ref resolver without module cycles.
Use existing real policy actions only. R0 runs under current rights; explicit
requested R1 draft can be admitted without per-tool approval. Read/admission
is not an effect receipt. No endpoint returns succeeded artifact or claims a
transaction committed when no executor exists.

R2/R3 approval domain binds complete server plan digest, actor/reviewer,
capability version/schema/resource revisions, exact destination and meaningful
amount/limits, expiry. Existing leader approval/SoD and explicit policy denial
apply. Scope-changing update means new immutable plan/version. Revoked/expired
approval, authority/capability/source drift prevent ready validation. No generic
approval substitutes for official-document issuance/checksum-bound review.

Budgets bound parent tool/model calls/tokens/wall-time/spend; defaults and hard
ceilings server-owned, not raised by callers. Transactional debit/reservation
prevents concurrent overrun. Unpriced live work stays inadmissible; no invented
provider rates/usage. Initial accounting is local/internal, no public client
endpoint can fabricate executed usage or successful business receipt.
Events contain IDs/digests/reason/build/request linkage, not arguments, source
text, secrets or chain-of-thought. Maintenance blocks mutations. Scope/owner
checks protect plan/approval/event reads as well as writes.
