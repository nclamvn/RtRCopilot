# TIP-024.6 — Answer Reliability Recovery

## HEADER

- **TIP-ID:** TIP-024.6
- **Project:** RtR Copilot V2
- **Module:** Query understanding · retrieval · grounded answering · evaluation
- **Depends on:** TIP-024, TIP-024.5
- **Priority:** P0
- **Approval:** Homeowner approved 2026-08-04 — answer quality may not be traded
  for latency, cost or demo availability.

## FOCUSED SCAN REPORT

### Stack and reusable controls

- FastAPI/Python 3.12, PostgreSQL/pgvector, Redis circuit breaker and budget,
  immutable SOT versions, ACL-before-content retrieval and citation lineage.
- Deterministic product registry already resolves HERA, VEGA and related RtR
  product names.
- External query rewrite seam already supports provider fallback but is disabled
  without explicit export policy and credentials.
- The web surface already renders grounded, honest-null and evidence states.

### P0 finding

The live question `Vega là gì?` produced a `grounded` run whose selected top
evidence was HERA range, the Sales Brief product list and CEO biography. The
correct current record `HC-002 — VEGA · Tactical heavy lifter` existed in the
same active corpus but was absent from top five.

Root causes:

1. OR lexical search retained Vietnamese function words (`vega | la | gi`).
2. The 64-dimensional offline hash embedding was allowed to decide semantic
   proximity without an entity/subject constraint.
3. Runtime answer generation copied the first three evidence blocks verbatim.
4. Grounding verified answer↔citation overlap, not question↔evidence relevance.
5. Existing quality fixtures were synthetic and source-scoped, so realistic
   HERA/VEGA/CEO distractors were absent.

## BLUEPRINT

```text
raw question (immutable)
  -> DLP / authorization
  -> deterministic QueryProfile (meaningful terms, registry entities, intent)
  -> optional external LLM rewrite (validated entities; original preserved)
  -> ACL-filtered hybrid candidate retrieval
  -> entity/subject-aware relevance rerank and hard reject
  -> wider answer candidate set
  -> external LLM grounded generation (strict JSON schema)
  -> external quality review
  -> deterministic question/evidence + claim/citation gates
  -> grounded persistence OR honest-null + governed gap
```

Runtime has no quality-degrading fallback. `OfflineExtractiveAnswer` remains an
explicitly injected test adapter. External processing is possible only when
`RAG_PROVIDER_MODE=external`, `internal` is explicitly allowlisted and at least
one provider credential is present.

## ACCEPTANCE CRITERIA

1. **VEGA definition regression**
   - Given the live mixed RtR corpus contains HERA, VEGA, product-list and CEO
     records, when `Vega là gì?` is retrieved, then `HC-002` is the primary hit
     and HERA-range/CEO records are not eligible definition evidence.
2. **No false-grounded fallback**
   - Given required LLM mode and no permitted credential, when Ask has relevant
     evidence, then the response is honest-null and no local extractive answer
     is persisted.
3. **Structured provider fallback**
   - Given primary provider failure and a valid fallback response, when Ask is
     generated, then the fallback result is parsed, reviewed and grounded with
     only known markers.
4. **Question/evidence relevance**
   - Given current cited evidence about HERA/CEO for a VEGA question, when the
     relevance gate runs, then generation is not allowed.
5. **Lexical hygiene**
   - `Vega là gì?` produces a lexical query containing `vega` and excluding
     `la`, `gi`; an all-stopword query produces honest-null.
6. **Grounding integrity**
   - Unknown/missing markers, unsupported factual units, wrong target entity,
     stale evidence and provider refusal remain rejected.
7. **Security and regression**
   - Backend unit/integration, web unit, browser/axe/keyboard, lint/type/build
     suites pass; live API and web containers are healthy.
8. **Measured quality gate**
   - Adversarial core suite has zero false-grounded answers; every accepted
     answer cites the expected target record family.

## CONSTRAINTS

- Never log API keys, raw external request bodies or private evidence.
- Never let LLM output create an entity outside the curated registry.
- Never lower ACL, freshness, provenance or DLP gates to improve answer rate.
- Never relabel a merely cited answer as grounded.
- Missing live credentials may defer live-provider verification, but not the
  deterministic, mocked-provider or full regression suites.
