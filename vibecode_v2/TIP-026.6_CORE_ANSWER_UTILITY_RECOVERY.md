# TIP-026.6 — Core Answer Utility Recovery

## HEADER

- TIP-ID: TIP-026.6
- Project: RtR Copilot v2
- Module: Enterprise Ask / retrieval / grounded synthesis
- Depends on: TIP-024.7, TIP-025, TIP-026, TIP-026.5
- Priority: P0
- Date: 2026-08-05

## CONTEXT

The first failing live snapshot exposed 267 candidate chunks, including
non-RtR synthetic sources that should never have remained active. After
quarantining those sources without deleting their history, the governed demo
corpus contains 219 active RtR records/chunks. The authoritative portfolio
record `L3R.2.005` is active and verified but originally sat after the first
200 chunks in
lexical `chunk_key` order. The current policy-first candidate scan stops after
200 allowed chunks before semantic ranking, so the authoritative record never
reaches the collection-anchor boost. The exhaustive coverage guard then rejects
the answer before the answer LLM is called.

The implementation-level TIP-026.5 tests use a three-record, source-scoped
synthetic corpus and therefore do not exercise this scale boundary. Live probes
also show atomic entity definitions succeeding while portfolio enumeration,
summary and comparison fail.

## FIX DESIGN

1. Add a generic priority-record lane to SOT retrieval. It loads metadata only
   for ontology-bound definition/collection record keys, applies the same policy
   decision, and only then adds allowed chunk IDs to the content query.
2. Keep the normal candidate lane bounded at its existing budget. Priority
   chunks are additive, de-duplicated and bounded by ontology schema limits.
3. Preserve deterministic collection coverage for names, while changing the LLM
   contract from “omit unsupported details” to “include the governed member and
   explicitly mark unavailable details.” This restores usefulness without
   turning the LLM into a source of truth.
4. Add live-scale integration coverage and a prompt-contract unit test. Rerun
   the real corpus portfolio probes after recreating the API.

## ACCEPTANCE CRITERIA

### AC-01 — Authority survives corpus scale

Given an authorized collection anchor positioned after more than
`rag_candidate_limit` ordinary chunks, when the collection is queried, then the
anchor reaches ranking and is selected.

### AC-02 — Policy remains fail-closed

Given a priority record denied by ACL or external-processing policy, when the
same query runs, then its content is not loaded, returned or cited.

### AC-03 — Candidate budget remains bounded

Given pinned records plus a large corpus, when retrieval runs, then the normal
candidate lane remains capped and pinned IDs are additive without duplicates.

### AC-04 — Useful exhaustive answer

Given a complete governed collection anchor and partial detail evidence, when a
user requests the full list and features, then the answer contains all governed
members, uses only cited details and explicitly identifies unavailable detail
instead of returning honest-null for the whole collection.

### AC-05 — Live regression

Given the active local corpus and approved LLM configuration, when the clean
Vietnamese portfolio question is sent through AnswerService/API, then it returns
`grounded`, cites `L3R.2.005`, contains all governed members and does not include
unsupported features as facts.

### AC-06 — No regression

Backend unit/integration, Ruff, mypy, web unit, TypeScript, ESLint and production
build pass; focused ACL/DLP and definition tests remain green.

## CONSTRAINTS

- Do not bypass ACL, DLP, lineage or citation validation.
- Do not special-case RtR product names in retrieval code.
- Do not increase a global top-k as the primary fix.
- Do not treat LLM output as enterprise truth.
- Preserve existing public API response shapes unless a typed additive field is
  proven necessary.

## IMPLEMENTATION OUTCOME

Completed on 2026-08-05. The recovery was implemented as a general enterprise
answer path rather than a product-name exception:

1. A policy-filtered authority lane scans ontology-bound metadata independently
   of the ordinary candidate cap; content is loaded only after ACL approval.
2. The original user wording owns ranking authority. LLM expansions are recall
   aids and cannot replace the original intent.
3. Governed collection anchors bind the complete member set; member records add
   detail. Missing detail is disclosed per member instead of invalidating the
   whole answer.
4. Vietnamese normalization preserves meaningful short acronyms such as RtR,
   CRM, UAV, AI, HR and IP while removing conversational filler.
5. LLM synthesis and an independent review pass operate only on selected,
   allowed evidence. A deterministic verifier then checks citations, lexical
   support, current lineage and collection coverage.
6. Citation normalization supports paragraph-end citations, short verdicts and
   headings only when the cited evidence lexically supports the preceding unit;
   unsupported prose still fails closed.
7. Simple definition and enumeration requests use an adaptive reasoning budget
   to reduce latency without weakening evidence or grounding gates.

Live acceptance returned grounded answers for colloquial company, CRM and
portfolio questions. The full portfolio request returned all 16 governed
values with 12 cited records and explicit unavailable-detail disclosures.
Unknown ORION returned honest-null and created a governed knowledge gap.
