# TIP-035.9 — Release Evidence Boundary Hardening

## Header

- Date: 13/08/2026
- Depends on: TIP-035.8R
- Priority: P0

## Problem

TIP-035.8R proved the answer runtime but exposed a release-process defect:
`tip034_pilot_capture.json` was tracked candidate source. A successful
post-build capture therefore dirtied the checkout and caused
`build-identity.sh` to invalidate the candidate that the report correctly
identified. TIP-033 also inherited an unnecessary image-build phase from the
generic E2E runner.

## Requirements

- REQ-035.9-01: all generated release reports, human ledgers and evaluation
  results must live under ignored `eval/runtime/` or outside the source tree.
- REQ-035.9-02: an in-repository path outside `eval/runtime/` must fail before
  an external runner starts.
- REQ-035.9-03: TIP-033 and TIP-034 must default to `E2E_SKIP_BUILD=1`.
- REQ-035.9-04: release preflight must read runtime evidence rather than
  tracked fixture/history paths.
- REQ-035.9-05: the TIP-034 definition check may use the immutable empty
  fixture, but operational observations and results must use runtime paths.
- REQ-035.9-06: existing TIP-035.8R evidence remains historical and is not
  rewritten or represented as evidence for a future candidate.
- REQ-035.9-07: local regression and full verification must perform no external
  LLM call.

## Acceptance criteria

1. `eval/runtime/` is ignored and accepted by the boundary checker.
2. Tracked or unignored in-repository report paths are rejected.
3. Both release wrappers bind runtime evidence and skip image builds by
   default.
4. Pilot campaign operational ledger, raw capture and result resolve below
   `/app/eval/runtime/`.
5. Preflight reads TIP-033 and TIP-034 evidence from the runtime evidence root.
6. Focused regressions, shell syntax, Ruff, mypy, full backend/web, production
   build, image scan and migration/data integration pass.

## Constraints

- Do not reuse the consumed TIP-035.8R external authorization.
- Do not send questions or evidence to an LLM.
- Do not modify the governed human observation fixture.
- Do not rebuild or recreate primary/pilot runtime services.
- Do not stage `_to_delete/`.

## Decision log

- A strict fixed in-repository root (`eval/runtime/`) is preferred over merely
  checking Git ignore rules. It is easier to audit and prevents path overrides
  from writing to any other candidate source location.
- Historical capture files may be committed as immutable audit records, but
  future campaigns never overwrite them.
