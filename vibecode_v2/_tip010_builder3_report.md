## DEVIATIONS (all L1)

- D1 — Package fingerprint is defined as sha256 over canonical `{source_key, scope, captured_at, adapter_version, payload_sha256}` and must match the manifest's declared value (`fingerprint_mismatch` otherwise); "fingerprint matches content" is therefore recomputable from package bytes alone. Identity-level violations (fingerprint/member/payload checksum, traversal, oversize, malformed archive) reject WITHOUT creating a registry row — a package whose declared identity cannot be verified must not poison fingerprint idempotency. Record-level violations reject as a persisted `rejected` package row (received→validating→rejected) so operators can see them. Both paths are typed and audited; both leave zero `research_records` rows.
- D2 — No upload-bytes endpoint: research packages are imported from `research_staging_root` by staging name, mirroring the TIP-006 SOT staging pattern exactly (the TIP-005 quarantine primitives are applied at parse: archive-entry validation reuses `ingestion.validators._validate_entry_name` — a private-name import with the existing `_effective_principal_ids` precedent). Builder 4's admin surface can add a byte-upload later without touching the contract.
- D3 — Research visibility rule (Builder 1 left it open): a research source/package/record is visible iff caller passes `view` on the source's classification AND (is source owner OR passes `curate`); search additionally requires the `search` action on `source_zone="research"` attributes. This matches Builder 2's gap/queue "owner OR curate + clearance" convention and makes research an explicit, separately authorized scope. Highly-restricted sources are invisible even to curators (clearance 2 < 3) — intentional, mirrors gap behavior.
- D4 — `answered → published` flip implemented record-level: publishing a package flips answered gaps whose *linked record* gained an activated version in that package (version-level would be unreachable since answering already requires an active version). Runs inside the activation transaction; per-gap `GovernanceError` is skipped (never blocks activation); audited as `governance.gap.publish`/`linked_record_activated`.
- D5 — Graduation claim shape: `claim_draft` is validated against `CandidateClaim` (claim_text, value, classification, confidence, version_ordinal, optional owner) at propose AND re-validated at approve (`graduation_claim_invalid`). The candidate enters the gate as `provenance/verification/fact = claim` with `source_key = graduation.<proposal-hex>` revision 1; version-ordinal/identity conflicts against an existing target record are deliberately left for the publish gate to reject (AC-09: gate can reject; no pre-gate shortcut).
- D6 — `research_source_unknown` (unknown OR policy-denied source at import) is deliberately one code — a curator without clearance for a restricted source cannot distinguish "doesn't exist" from "denied". Same collapse for `research_record_not_graduatable` (missing/unimported/inactive/policy-denied).
