# TIP-026.5 — Completion Report

**Status:** IMPLEMENTED · ACTIVATION PENDING
**Date:** 2026-08-05
**Scope:** Enterprise LLM query planning, governed collection retrieval,
coverage-gated synthesis and portfolio-answer recovery

## Outcome

The failure shown by “Các sản phẩm của RtR là gì?” has been corrected at the
architecture level. RtR Copilot can no longer treat an exhaustive request as a
generic lookup and return the first approved but off-intent passage.

The new pipeline separates four concerns:

1. an approved LLM interprets informal language and proposes a strict semantic
   plan;
2. the governed ontology validates the proposed entity, collection and answer
   boundary;
3. ACL/DLP-first retrieval obtains the authoritative collection anchor and
   supporting evidence;
4. deterministic coverage and citation checks verify the LLM synthesis before
   it can be returned.

The LLM is therefore used for language understanding and evidence-bound
synthesis, not as a source of company truth.

## Root cause

1. TIP-025.1 intentionally restored an evidence-only fallback so Ask remained
   available without an external provider.
2. The old `QueryPlan` could represent definitions and lookups, but not
   exhaustive enumeration, completeness, list layout or a governed collection.
3. Top-k retrieval optimized local relevance rather than proving that a
   complete set had been retrieved.
4. `StrictEvidenceAnswer` was allowed to answer a composite question by copying
   an evidence snippet. The result could be cited and still fail the user.
5. Empty API-key strings were treated as configured credentials, producing a
   false `ready` signal and an invalid empty Bearer header.

## Implementation

- Added generic governed ontology collections with typed members, owner,
  lifecycle, provenance and authoritative record keys.
- Added the RtR portfolio as the first data instance, bound to `L3R.2.005`:
  **13 products, one bundle, one service row and one placeholder row**. The
  latter two cannot be silently presented as products.
- Extended the external planner schema with intent, completeness, answer shape,
  collections, search expansions, retrieval subqueries and clarification state.
- Made the planner OpenAI-primary with an optional Anthropic fallback, each
  timeout/breaker/budget bounded and export-policy gated.
- Restricted every LLM entity/collection choice to a bounded ontology-derived
  candidate catalog. Invented choices are discarded.
- Added collection-anchor ranking and exact record-key binding.
- Added deterministic pre-generation coverage: an exhaustive answer is denied
  unless the authoritative anchor contains every governed member.
- Added deterministic post-generation coverage: a generated list is rejected
  unless the final answer contains every required member.
- Prohibited evidence-only mode from answering enumeration, comparison,
  procedure, summary or analysis plans.
- Preserved atomic evidence-only definitions only for explicit local/test
  mode. External-quality mode now forbids every silent downgrade.
- Fixed credential readiness so blank secrets produce
  `configuration_required`, `UnavailableLLMAnswer` and `OfflineRewriter`
  rather than false readiness or a lower-quality answer.
- Added three corpus acceptance cases: clean Vietnamese, informal Vietnamese
  without diacritics and English. Each requires `L3R.2.005` and all 16 governed
  values.
- Added a synthetic People-policy collection to prove the contract is
  domain-agnostic and does not contain a product-specific code branch.
- Stabilized one pre-existing browser geometry test by waiting for the
  authenticated Files workspace before measuring it.

## Resulting answer contract

For a question such as “rtr co nhung san pham nao vay, liet ke het giup minh”:

1. the LLM planner must classify it as
   `enumeration / exhaustive / list`;
2. the registry must bind it to `rtr.catalog.product-portfolio`;
3. retrieval must include the current `L3R.2.005` anchor;
4. the anchor and the final response must cover all 16 values;
5. the answer must visually distinguish products, the HERA + VEGA bundle,
   `Dịch vụ`, and the `Chưa xác định` CRM placeholder;
6. unsupported descriptions are omitted or identified as unavailable rather
   than invented;
7. unrelated company identity, founder or other high-ranking facts cannot be
   used to pad the response.

## Operational state

The code path is implemented and all hermetic quality gates pass. The local
stack is intentionally not advertising quality-LLM readiness because there is
no non-empty OpenAI or Anthropic credential:

- operational capability: `grounded_answering=configuration_required`;
- answer provider: `UnavailableLLMAnswer`;
- query planner: `OfflineRewriter`.

Consequently, every Ask now abstains with
`answer_quality_configuration_required` until an approved provider is active.
This deliberately favors answer quality over degraded availability.
