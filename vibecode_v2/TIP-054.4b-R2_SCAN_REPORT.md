## Proposal A — compatible initial reads in one owned session

First lane: all steps are exactly host `sot.read`, version2, effectR0,
implementation `sot.read`, view policy and response destination. Preserve existing
20-step/20-reference bounds. A PlanPayload must satisfy actual host digest/schema/
arguments/build checks, not merely claimed fields. R1, mixed/legacy/unknown work
keeps the old path. R1's DocumentOS bind performs content and nested service work;
holding a borrowed checkout across it risks capacity starvation, and is not
included in this first candidate.

Exact proposed files/calls:

- `actions/source_metadata.py`: extract the unchanged SQL load into a private
  session-taking function and unchanged row classification into a pure helper.
  Existing `resolve_action_sources` owns/closes its checkout as before. A separate
  borrowed-session resolver performs fresh SQL for every call, no row/frame cache.
- `actions/policy.py`: optional borrowed initial session for `_payload`'s scope,
  sources and R0 step resource checks; use actual fresh `project_subject` and
  `session_resource` SQL. Do not use locked `session_current` for initial reads.
  Only the strict lane passes that session; public/default behavior stays old.
- `actions/service.py`: `_contract`, `_payload` and `_revalidate` accept the
  private initial session. `create_plan` owns one short initial read checkout for
  current, payload and the separate post-binding sources call. It closes BEFORE
  the mutation UOW. All original source calls and deterministic rebind remain.
- `actions/execution.py`: load persisted plan, run executable checks and full
  `_revalidate` inside one initial read checkout. Close before the existing
  mutation UOW; `_view` stays a distinct post-commit checkout.

Borrowed ownership is explicit: helpers never close a caller session and never
open nested sessions on this lane. If either sources call detects unsupported
actual topology or requested evidence overflow (>1000 active ROWS, bounded1001),
raise an internal whole-attempt fallback signal. The owner exits/closes the
initial checkout, discards the whole candidate, then invokes the unchanged
old initial path fresh. No partial result, body or borrowed session reaches the
shared resolver. Missing/denied/checksum-invalid input remains denial, not an
unsupported-success fallback. Generic lineage may safely use the unchanged
same-session discovery plus final overlay; no attributes survive the final await.

READ COMMITTED statements remain fresh. Session reuse is NOT permission reuse:
each source/current/resource checkpoint projects real current authority; final
mutation/disclosure frames remain independently fresh after locks. Entitlement
row selection and conservative ACL semantics retain transaction time, so a longer
initial transaction can conservatively deny a grant that begins mid-session.
It must never grant an expired or later-revoked permission. This conservative
parity boundary needs explicit approval and a real temporal test; do not silently
substitute statement time for approved transaction predicates.

Ordinary R0 target: admission29SQL/3checkouts instead of29/7; submit21SQL/3
instead of21/7, before Proposal B. No query call is deleted or result cached.
Context-packet/multistep counts are separate bounded shapes, not that exact oracle.
