## Problem statement

An evidence-only answer can be factually quoted and still fail the user's real
request. For example, an exhaustive portfolio question currently becomes a
generic lookup, retrieves a few high-ranking RtR passages and returns the first
approved chunk verbatim. The result is cited but incomplete and off-intent.

The failure is architectural:

1. the planner cannot represent exhaustive enumeration, answer shape or
   collection coverage;
2. retrieval optimizes top-k relevance, not completeness;
3. the evidence-only adapter is allowed to answer composite questions that
   require synthesis;
4. no gate proves that the answer covers the governed collection requested by
   the user.

This TIP treats groundedness and answer adequacy as separate mandatory gates.

## Decisions

1. Every eligible Ask uses an external LLM as a semantic planner before
   retrieval. The LLM interprets intent and proposes a bounded plan; it never
   creates truth, permissions, entities, collections or evidence.
2. The governed ontology gains generic collection metadata. A collection binds
   a named enterprise set to its subject, members and authoritative SOT record
   keys. Products are the first data instance, not a code branch.
3. QueryPlan carries intent, completeness, answer shape, selected collections,
   required members, retrieval subqueries and planner provenance through all
   downstream stages.
4. Exhaustive/composite questions require a successful external plan, a
   collection anchor, evidence coverage and reviewed LLM synthesis. If any gate
   is absent, Ask abstains with a typed reason. It never falls back to a raw
   top-k extract.
5. Local/test mode may retain a narrow evidence-only adapter. Once the product
   is configured for external-quality mode, every eligible Ask requires the LLM
   planner and reviewed LLM answer path; missing/failed LLM service never
   silently downgrades, including for atomic questions.
6. The answer LLM receives only ACL/DLP-authorized current evidence. A second
   review pass and deterministic citation, entity, collection and coverage
   checks remain mandatory.

## Target flow

```text
raw question
  -> deterministic normalization + ontology candidates
  -> approved LLM semantic planner (strict JSON)
       intent / completeness / answer shape / collection / subqueries
  -> registry validation and immutable QueryPlan
  -> clarification or planning-required gate
  -> ACL-first retrieval
       collection anchor + member/detail evidence + bounded expansion
  -> deterministic coverage gate
  -> reviewed LLM synthesis from authorized evidence only
  -> citation + relevance + coverage verification
  -> grounded answer OR typed abstention
```

## Acceptance criteria

1. “Các sản phẩm của RtR là gì?” and noisy Vietnamese/English variants produce
   an `enumeration + exhaustive + list` plan for the governed RtR portfolio.
2. The plan selects only collections/entities present in the bounded ontology
   catalog; invented planner output is discarded.
3. Retrieval includes the current authoritative collection record and does not
   pad the answer with unrelated company, founder, salary or legal facts.
4. An exhaustive answer is impossible unless every governed collection member
   is present in the anchor evidence and the final answer covers every member.
5. Evidence-only mode cannot return a grounded answer for a synthesis-required
   plan; missing/failed LLM planning or synthesis produces a typed safe refusal.
6. Atomic definition questions continue to resolve exact aliases and cannot
   drift to another entity.
7. The architecture is proven with at least one synthetic non-product
   collection, demonstrating that expansion is registry-data work rather than
   product-specific query code.
8. Planner/generator credentials never override external-processing policy;
   ACL, DLP, provenance, freshness, budget, breaker and immutable audit gates
   remain intact.
9. Audit metadata records counts/digests and planner/coverage decisions without
   storing collection member names, user text or evidence plaintext.
10. Ruff, mypy, backend unit/integration, real-world evaluation, web/browser and
    production build gates remain green.

## Non-goals

- The LLM is not a source of enterprise truth.
- This TIP does not infer ungoverned ownership relationships.
- This TIP does not claim that a CRM placeholder is a standalone product; the
  answer must preserve the collection's governed item kind.
- This TIP does not weaken abstention to improve answer rate.
