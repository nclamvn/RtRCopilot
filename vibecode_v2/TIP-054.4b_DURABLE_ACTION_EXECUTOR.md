## Task / approved implementation seam

Add real DBOS execution behind the existing Action Kernel, not another fake
engine or a copy of the synthetic bake-off source. Reuse real current domain
policy and canonical source services. Retain existing Ask/ingestion/reindex/
Documents worker ownership; no migration of those pipelines to DBOS.

1. Admit exact DBOS 3.2.0 only after actual serving-pinned import/workflow/
   PostgreSQL proof; retain dependency/source/license evidence. Do not upgrade
   serving SQLAlchemy/psycopg to the bake-off's isolated versions. Pin minimal
   admitted dependencies and preserve unrelated lock entries.
2. Separate DBOS system database/schema and worker entrypoint; default disabled
   configuration, no private environment edits or automatic production bootstrap.
   Runtime role must not gain business DB owner/superuser grants. Validate
   misconfiguration/redact credentials and framework internals in public errors.
3. Keep v1 host capability hashes/contracts and contract-only run/history
   semantics intact. Add explicit v2 executable R0 `sot.read` / R1
   `documents.create_draft` output schemas and bounded attempt limits, rather
   than executing v1's admission-only output schema. Dynamic runtime availability
   must not misrepresent a disabled/unconfigured runner. R2/R3 execution remains
   unavailable regardless of an approval record; no real external adapters.
4. Add schema 0019 execution domain ledger, step attempts/business receipts/events
   distinct from existing immutable contract-admission history. These exact
   structures derive the already-approved Blueprint executor/attempt/receipt
   lifecycle. Typed state transitions, append-only history, foreign keys,
   monotonic finite parent usage/deadline, ownership epochs/final publication
   fence and least-privilege runtime grants must be enforced and tested.
5. Submit/status/cancel/resume endpoints return bounded durable state, never
   synchronous `get_result` or a blocking thread waiting through native recv.
   Stable durable IDs make repeated submit/recovery idempotent; a persisted
   dispatch intent repairs a DB→engine submission gap. Finite poll/sleep/backoff,
   explicit worker lifecycle/cleanup and version binding; no request-path
   implicit SDK launch/schema creation. Restart must recheck current authority.
6. R0 stores only bounded source refs/output digest in engine/events/receipts;
   content delivery refetches/revalidates current rights/source/purpose. R1 uses
   existing canonical DocumentOS job keys and result/artifact publication.
   `job_accepted` is not generated-file success. Actual verified source status,
   object/version/checksum and current access determine the business receipt.
7. Approved narrow DocumentOS hook: optional host-owned same-session guard
   immediately before canonical source mutation/reconciliation and final
   publication for action-linked jobs. Bind the immutable action run/plan/step
   key to the job; validate current purpose/source/actor and action cancellation
   plus source render ownership. Unlinked existing endpoints keep behaviour.
   No callback/code/reference chosen by a client/model becomes authority.
   An action lease fence alone cannot claim to revoke the separately-owned
   document renderer; its own final fence and current linked-run guard matter.
8. Approved output-security seam: new action-origin artifacts inherit maximum
   source/template classification, immutable purpose/source bindings and current
   source access through both Documents and Files preview/download/detail paths.
   Narrow linked-output guard only; ordinary/unlinked existing files unchanged.
   Canonical reuse must not bypass these bindings. Host-owned policy namespace
   in the action canonical key, or an explicit unsafe-reuse refusal, is permitted;
   never retrofit a cancelling action's authority onto an ordinary shared job.

  publish a staged file or cause a second effect. A workflow-ID check alone is
  insufficient. Retain actual process/DB evidence, not fixture flags alone.

- EXE-007: Given retry/child/recovery, all actual attempts charge the same finite

  All samples/failures and resource/profile boundaries retained.
- EXE-010: Given populated old/new domain state, migration/down/up retains old
