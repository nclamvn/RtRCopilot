Selected three-lease design retains ONE request-local Task and irreversible
mutation/outcome state, but creates a fresh guarded physical facade/factory/Session
for each phase. Actual initial transaction rollback/close precedes checkin;
original UOW mutation genuinely commits/rolls back before checkin; final persisted
metadata/view reacquires a new lease and fresh transaction. These are three lease
GENERATIONS, not necessarily three PostgreSQL PIDs or distinct driver connections:
pool reuse is legitimate. Generation identity, checkout/checkin order and real
txids/clocks prove the boundary; PID distinctness is not the contract.

Builder's proposed interfaces keep `read_phase(commit=False)`, `mutation_phase()`
and `_owner` forwarding; `connection` is the exact live generation orNone.
No ambient factory redirect or permission/result cache. Unsupported/clock/R1/
legacy initial fallback closes its generation before the complete old path once.
No fallback/replay after mutation starts, uncertain commit or poisoned cleanup.

## Required design controls before authoring

1. Current Connection SQL guards inspect mutable owner's current Session. After
   rotation, every Connection must pin immutable generation AND exact identity;
   every Session and transaction facade must pin its own generation. Old handle
   execute/scalar/scalars/exec_driver_sql/start/close/invalidate must reject before
   delegate during newer active generation, same Task and child Task. This is a
   new-design requirement, not a confirmed560174 defect.
2. Closing/invalidation must capture the exact departing Connection, not consult
   a later mutable owner field. Keep phase/cleanup busy until joined Session
   terminal + physical checkin/invalidation finishes. Never acquire a replacement
   while uncertain cleanup is running; a cleanup failure poisons further phases.
   Terminal child has only exact-resource terminal authority, no SQL/phase borrow.
3. Poison/outcome/mutation state survives each physical release. A preserved
   primary `LegacyInitialRequired` with close/invalidate failure notes must NOT
   accidentally trigger old fallback; public create/submit catches must require
   successful released initial state, not exception type/mutation flag alone.
   Preserve primary cancellation/error semantics without interpreting it as
   successful cleanup, rollback or business success.
4. Mark mutation lifecycle conservatively and once-only; failure/acquire cancel
   must not reopen the optimized attempt. No new timer after any acquisition.
   Final reacquisition may fail after actual durable commit: truthful503/error,
   independent status and idempotent retry, never captured precommit success.
5. Maintain original maintenance→key/run→input/evidence→ledger staging→audit→NEW
   authority→business/audit commit. Preserve postcommit source disclosure guards.
   Submit/status owner metadata is not source-content authority; do not add a
   source-clearance requirement to its final `_view` or owner status/cancel.

Baseline closure, final adaptation inventory and explicit authoring ACK remain
blocking prerequisites to edits, not product defects. Exact poison/fallback and
generation interfaces need Contractor review before tests use them.
