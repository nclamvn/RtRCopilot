# TIP-035.15 — Release Automation Nounset Hardening

## Header

- Date: 14/08/2026
- Depends on: TIP-035.14
- Trigger: isolated versioned deploy drill
- Priority: P0

## Context

The versioned deploy drill failed before building because macOS Bash 3.2 treats
an empty array expansion as an unbound variable under `set -u`. The shared CI
helper correctly initialized `RTR_COMPOSE_BUILD_ARGS=()`, but `deploy.sh` and
`ci-local.sh` expanded the empty array directly. A normal build with no sandbox
workaround therefore crashed while a sandbox build with one optional argument
would proceed.

## Requirements

- REQ-035.15-01: normal builds with zero optional compose arguments must run
  under Bash nounset mode.
- REQ-035.15-02: sandbox builds must preserve every optional build argument.
- REQ-035.15-03: deploy and local CI must use one shared expansion boundary.
- REQ-035.15-04: the fix must not disable `set -u`, migration, health, image
  tagging or version-ledger gates.
- REQ-035.15-05: a regression must cover both call sites and reject restoration
  of the unsafe direct expansion.

## Acceptance criteria

1. Bash syntax validation passes for the shared helper, CI and deploy scripts.
2. The release evidence unit suite passes.
3. A functional isolated deploy with no sandbox build workaround completes all
   six stages and reaches the hardened health gate.
4. The remediation is committed before any final candidate rebuild or
   certification is accepted.

## Decision log

- The empty-array branch belongs in `rtr_compose_build`, not duplicated at each
  caller.
- Nounset remains enabled; weakening shell safety is not an acceptable fix.
- Load evidence from the pre-remediation SHA is diagnostic only and must be
  rerun after the final candidate is committed.
