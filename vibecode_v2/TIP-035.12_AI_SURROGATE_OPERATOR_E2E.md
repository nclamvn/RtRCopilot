# TIP-035.12 — AI-Surrogate Operator E2E

## HEADER

- TIP-ID: TIP-035.12
- Project: RtR Copilot V2
- Module: Enterprise release certification
- Depends on: TIP-035.11 and the immutable TIP-034 campaign
- Priority: P0
- Date: 14/08/2026
- Method: Vibecode Kit v6.1 — Contractor / Builder / Homeowner

## CONTEXT

The Homeowner directed the project to replace manual operator-testing steps
with an LLM-authored, employee-like E2E campaign. This is a release-governance
change, not permission to impersonate an employee or to relabel AI output as a
human attestation.

TIP-034 already has a build-bound 27-case technical capture across company,
product, commercial, operations, systems, methods, safety and conversation.
What remained absent was an operator-facing test layer that repeatedly drives
the UI using realistic personas and binds its result to the same build and
immutable questions.

## TASK

Implement a local-only AI-surrogate operator gate that combines:

1. the real build-bound TIP-034 technical capture;
2. a persona-driven browser E2E over the exact 27 cases;
3. immutable question, manifest, ledger and report digests;
4. an explicit Homeowner opt-in before release preflight may accept the
   surrogate in place of manual tester observations.

## REQUIREMENTS

| ID | Requirement |
|---|---|
| REQ-035.12-01 | Use exactly the 27 immutable TIP-034 cases and all seven governed domains. |
| REQ-035.12-02 | Exercise general-staff, sales/project, engineering/operations, management/governance and adversarial/unclear personas. |
| REQ-035.12-03 | Verify exact input round-trip, composer clearing, visible processing, expected response state, citation/honest-null boundary, Evidence Rail consistency, follow-up context and prompt-leak absence for every case. |
| REQ-035.12-04 | Bind the surrogate result to the exact technical-capture build and reject stale, partial or cherry-picked reports. |
| REQ-035.12-05 | Keep the human ledger unchanged and record `human_usefulness_measured=false`. |
| REQ-035.12-06 | Execute zero external calls; browser answers are synthetic UI oracles and never claim to retest live generation. |
| REQ-035.12-07 | Keep the default browser suite independent from release evidence. |
| REQ-035.12-08 | Preflight accepts the surrogate only when `TIP035_AI_SURROGATE_APPROVED=1`; otherwise it remains blocked. |

## ACCEPTANCE CRITERIA

1. All 27 case IDs, question digests and expected states match the governed
   source suite and immutable manifest.
2. Technical capture is 27/27, citation accuracy 1.0, false-grounded 0 and p95
   within 25 seconds on the same build.
3. Persona browser E2E passes 27/27 with eight checks per case.
4. Human-ledger SHA-256 is unchanged and no AI observation is written to it.
5. Result states `ai_surrogate_not_human_attestation`, records residual risk and
   contains no question, answer or evidence plaintext.
6. Normal Playwright regression excludes the release-only spec and remains
   green.
7. Release preflight remains fail-closed without the explicit override flag.

## CONSTRAINTS

- No external LLM/API call is authorized or executed by this TIP.
- No human usefulness score is invented.
- Synthetic browser responses test the operator surface only; the separate
  technical capture remains the answer-generation oracle.
- A new commit changes candidate identity. The current result cannot certify a
  later commit and must be rerun after rebuild and recertification.
- Production OIDC/TLS/secrets, operational drills and Homeowner GO remain
  independent gates.

## DECISION LOG

- The Homeowner explicitly authorized an AI/LLM surrogate to replace the
  pre-release manual operator-test step.
- The replacement is implemented as a transparent override path, not a silent
  weakening of TIP-034.
- Human observations remain useful optional evidence, but are no longer the
  only path through the operator-acceptance gate when the Homeowner activates
  the AI-surrogate override.
- Actual company rollout still begins as a controlled cohort with stop and
  rollback criteria; automated testing does not eliminate production
  monitoring.
