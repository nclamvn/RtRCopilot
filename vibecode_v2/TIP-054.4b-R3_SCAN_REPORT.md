## 5. Transaction clock, fallback, task and cleanup invariants

Actual Admission-read SQLAlchemy2.0.43 package excerpts are retained at new raw
`sa2043_external_transaction_source.txt` (Builder read all268 lines). External
Connection binding has autocloseFalse. With no active connection TX, Session
creates conn.begin with should_commitTrue. With an existing external root TX,
default conditional_savepoint becomes rollback_only, and Session.commit does
NOT commit that root. Therefore Python Session.in_transaction alone is NOT proof.
Require real PG txid/transaction_timestamp per phase, physically transaction-free
entry/exit, and actual independent xact-lock acquisition after mutation commit.

Initial grouped transaction semantics stay conservative; rm/gm/sm membership
statement clocks, em transaction-time expiry predicate and fresh PolicyContext
expiry are unchanged. em has NO valid_from/birth predicate. Role/group/scope/ACL,
source class/current pointer/purpose/freshness/capability/evidence must be freshly
projected after all blocking locks in mutation AND final create disclosure.
No frame is carried as authority across phase boundaries or waits.

Unsupported topology/evidence overflow or typed InitialClockDenied is the ONLY
whole-attempt fallback eligibility already approved in R2. Initial phase ends,
physical owner closes/checks in, then complete unchanged old initial path runs
ONCE with optimizedFalse. No lease remains held when shared fallback opens its
own sessions. No half-batch result, bound permission or current-only ACL grant
survives. Hard graph/schema/checksum/pointer/source/purpose/status/security/build/
capability/budget failures stay direct; no general ActionError/connection failure
retry. A fallback may re-read its initial immutable plan and use additional old
checkouts; ordinary1-checkout budget does not apply to it. No mutation has occurred
before initial fallback, so this does not replay an unacknowledged COMMIT.

Owner identity is asyncio.current_task object, not inherited ContextVar. All phase
entry/use requires that owner and active-phase exclusivity. Child task/gather/
nested borrower use fails BEFORE SQL; no physical connection is passed to DBOS,
background dispatch or DocumentOS. Different concurrent requests use different
owners even when callers inject the same service object. No service-wide mutable
lease/factory field, trusted bound View or permission cache is introduced.

Actual SQLAlchemy AsyncSession/AsyncConnection __aexit__ shield child close tasks.
Cleanup child is allowed ONLY to finish rollback/session close/connection close,
not execute product SQL or borrow a phase. Join cleanup before final response or
propagating cancellation; preserve original CancelledError, never return success
because cancellation occurred. Repeated cancellation must not leave a detached
task/checked-out connection. On broken driver/reset, invalidate actual connection
and verify pool return; never retry business mutation automatically. No new
public timeout/cleanup configuration or cancellation suppression is proposed.
Use a single tracked cleanup task/future, not a new task/close attempt per cancellation.
Repeated owner cancellation records the original cancellation and waits for the
SAME shielded cleanup; it never clears the cancellation into a business success,
restarts SQL, reopens a connection or returns while the cleanup child is detached.
This bounds cleanup resources/attempt count, not an invented wall-clock guarantee.
Actual installed-driver close/terminate behavior and finite repeated-cancel proof
must be read/executed by the fixture owner before this detail is approved. Do not
add an arbitrary new cleanup timeout or extend the operation budget silently.
Finite fixture tests must demonstrate termination/return under cancellation and
disconnect; this scan does NOT claim a hard network-outage cleanup bound. If that
cannot be met within unchanged API/load budgets, stop and escalate, not waive.

Preferred lease retains _view AFTER successful actual mutation context exit.

unless durable status is independently read later. Same plan/run/idempotency keys
reconcile against actual ledger and chain; duplicate never resets spent/cancel/
deadline/epoch or adds another success audit. No SDK dispatch occurs before commit.

Status/cancel metadata remains active-owner-only and accessible after source
permission loss. Content/read_output/new or duplicate submit rechecks source
rights separately. Lease scope does not conflate the two. Create still can persist
an authorized plan, then deny its response after postcommit source revocation;
that is the existing guarded contract, not automatic rollback of the plan.

Precommit submit-view alternative would be a committed-admission snapshot, not
latest state at current postcommit read. With concurrent worker/cancel it could
omit new receipts/epoch or state that old _view observed. Returning only after
commit prevents speculative success but does not preserve observation timing.
Row+receipt queries add audit-held work. This alternative requires Root to approve
that internal linearization change and corresponding exact concurrency proof;
it is NOT silently folded into preferred lease.
