# TIP-026.3 — Corpus-wide Office Glyph Recovery

**Priority:** P0 document trust
**Depends on:** TIP-026.2
**Status:** COMPLETE

## Evidence

The live `RtR_Sales_Brief_Template_v1.1_ENG VIE.docx` viewer is still backed by
generator v1. Its 8,419-byte PDF uses unembedded Helvetica, ZapfDingbats and
Symbol fonts and visibly replaces Vietnamese glyphs with black squares.

TIP-026.2 changed future Office rendering and repaired one PPTX only. The live
database still has ten active DOCX/PPTX previews from generator v1 and one from
generator v2. A v2 probe of the Sales Brief produces a visually correct,
font-embedded six-page PDF, but the Unicode validator rejects it at 84.98%.
The false failure comes from `python-docx` returning the same merged table cell
for multiple grid positions, causing the expected character multiset to count
visible Vietnamese text twice.

## Root cause

1. Legacy Office renditions were not invalidated or migrated when the renderer
   contract advanced.
2. The DOCX fidelity baseline counted merged-cell aliases as separately visible
   text.
3. The viewer manifest did not fail closed for a stale Office preview.
4. No repeatable corpus backfill command existed; the prior recovery was a
   one-off operation.

## Task

1. Deduplicate merged Word cells by physical XML cell identity while preserving
   the table grid shape and structured locators.
2. Require every Office preview font to be embedded and reject replacement
   glyph markers not present in the source.
3. Advance the ingestion/generator contract to v3.
4. Prevent the viewer API from serving stale Office visual renditions; retain
   structured text and report a typed stale-preview warning until recovery.
5. Add a dry-run-by-default, audited command that identifies and re-renders all
   stale active DOCX/PPTX versions through the normal job pipeline.
6. Apply the backfill to the local pilot corpus and verify every active Office
   preview by provenance, font embedding, Unicode text and raster inspection.

## Acceptance criteria

- **AC-01:** Sales Brief renders as six pages with its original layout and no
  black Vietnamese replacement boxes.
- **AC-02:** Merged Word cells occur once in the fidelity baseline and later
  aliases are represented as empty grid cells.
- **AC-03:** Office preview publication fails if any used PDF font is not
  embedded, if Unicode fidelity is below 98%, or if an introduced replacement
  marker is detected.
- **AC-04:** An Office preview whose generator version differs from the current
  version is not exposed as a visual rendition.
- **AC-05:** The backfill is dry-run by default, uses durable ingestion jobs and
  leaves failed legacy renditions active until a verified replacement exists.
- **AC-06:** After apply, every active Office preview in the pilot corpus is
  generator v3; prior matching artifacts are `superseded` and auditable.
- **AC-07:** Corpus QA checks all active DOCX/PPTX previews for embedded fonts,
  replacement markers, parseability and page count; representative raster pages
  are visually inspected.
- **AC-08:** Backend, web, browser, lint, type and production build gates pass
  with concrete counts.

## Constraints

- Never overwrite originals or existing rendition objects.
- No cloud conversion and no authorization bypass.
- Backfill must use the same sandbox, provenance and atomic publication path as
  a normal ingestion job.
- A conversion failure must fail closed without hiding the last active preview.

## Decisions log

- This is a P0 reliability correction within the approved local-rendering
  architecture, so no new Blueprint checkpoint is required.
- Pipeline/generator advances to v3 because validation and publication semantics
  changed after v2.
