## Files / verification

Created `v2/experiments/durable_runtime/temporal_adapter.py`. It uses real
`Client`, `Worker`, Workflow / Activity decorators and finite `RetryPolicy`;
starts or reattaches stable durable IDs; runs shared source work only inside
an Activity; and returns only actual Activity results. Default activities have
three attempts, 5-second start-to-close and 30-second schedule-to-close limits.

Native extras implement a persisted resume signal / wait condition, an owner
process held for supervisor SIGKILL, actual history export, and real SDK
`Replayer` checks for original, separately coded compatible (new harmless
metadata) and deliberately incompatible (first timer instead of source
activity) implementations. Exported histories and implementation source have
SHA-256 fields. At initial static inspection these paths were implemented but
not yet execution-certified; retained actual proofs are recorded below.

Static commands: host `ast.parse` passed after initial and revised source;
`git diff --check` returned exit 0. Neither imports the SDK nor tests runtime
behavior. At that initial check, actual commands/results still awaited the
shared fixture; subsequent sections record their execution. No
benchmark cell is filled by provenance research or syntax checks.
