# TIP-035.18 — Production Configuration Closure

## Header

- Date: 15/08/2026
- Depends on: TIP-035.17 and build-bound TIP-033/TIP-034 certification on
  candidate `fc3284015a5f632233a993155506c96154038469`
- Module: Production cutover control plane
- Priority: P0

## Context

The release preflight correctly kept `production_configuration` blocked, but
its implementation only constructed the backend `Settings` object from an
operator file. That check could not prove deployment concerns outside the
application: exact candidate binding, real TLS material, hostname coherence,
file permissions, HSTS, explicit ingress binding, DSN/password separation or
connector-off state. The repository also did not explicitly ignore the
canonical `.env.production` filename.

This TIP closes the production configuration *contract*. It does not invent or
approve RtR's real domain, OIDC tenant, certificate, secrets or backup target.
Those remain operator-owned inputs and the release stays fail-closed until they
are supplied.

## Requirements

- REQ-035.18-01: provide one tracked, content-free production template and an
  idempotent operator command that creates the real profile with mode 600 and
  never overwrites it.
- REQ-035.18-02: explicitly ignore `.env.production`; filled credentials and
  certificate material must never enter source control or release identity.
- REQ-035.18-03: validate a fully materialized profile without sourcing it or
  emitting values; shell interpolation, placeholders and overly broad file
  permissions fail closed.
- REQ-035.18-04: bind production to one exact clean candidate SHA, HTTPS public
  origin, independent HTTPS OIDC issuer, corporate domain policy and valid JSON
  group mapping.
- REQ-035.18-05: prove unique secret separation, owner/runtime DSN password
  coherence, approved internal external-processing policy, provider credential
  availability and connector-off state.
- REQ-035.18-06: prove production TLS certificate/key validity, match, hostname,
  minimum remaining lifetime, HSTS and ingress/public-origin coherence.
- REQ-035.18-07: retain application-level validation inside the locked backend
  image and harden `Settings` against development build IDs, empty domain
  policy, malformed group mapping and half-configured external providers.
- REQ-035.18-08: make the TIP-035 release preflight consume only the new
  content-free runtime verdict and document the exact operator closure flow.

## Acceptance criteria

1. The complete synthetic production contract passes the standalone validator
   without any domain or secret value appearing in its report.
2. Placeholder secrets, reserved/mismatched origins, broad file permissions,
   connector activation, local TLS and short HSTS each block deterministically.
3. Production `Settings` refuses development build IDs, empty corporate domain
   policy, invalid group mapping and external mode without both policy and a
   provider key.
4. `.env.production.example`, `.gitignore`, Compose ingress binding, Make
   commands and the release preflight agree on one production contract.
5. Missing real operator inputs remain a truthful blocked gate; no synthetic
   credential may be promoted as release evidence.
6. Focused tests, Ruff, mypy, shell syntax, Python compilation and diff hygiene
   pass without external provider calls.

## Constraints

- Never source the production env file in a shell.
- Never print or hash raw secret values into tracked evidence.
- Never generate an OIDC tenant, corporate domain, TLS certificate or
  production secret on behalf of the Homeowner.
- Never activate an enterprise connector in this TIP.
- Do not run TIP-033/TIP-034 or any external LLM/embedding call.
- Current certification remains historical after these source changes are
  committed; a new candidate rebuild and recertification require their own
  approved steps.

## Decision log

- Deployment validation is standard-library Python so it can run before the
  application starts and without importing a secret-bearing settings object.
- The final gate is layered: deployment/TLS contract, Compose materialization,
  then application `Settings` inside the image.
- Evidence stores only fixed error codes, booleans, counts and non-secret
  digests under ignored `eval/runtime/`.
- Real certificate files are required; `INGRESS_TLS_MODE=internal` is valid for
  local drills only and cannot close production.
