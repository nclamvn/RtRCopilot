# TIP-026.4 — Application-wide Compact Density

**Priority:** P1 product usability
**Depends on:** TIP-024.5, TIP-026.3
**Status:** COMPLETE
**Date:** 2026-08-05

## Problem

Application chrome consumed too much of the viewport. At 1280 × 720 the Files
page header was 102 px high, the main content used 48 px horizontal gutters,
the catalog was 250 px wide and each format filter occupied 103 × 40 px. The
actual viewer canvas was only 470 px high.

## Design decision

Adopt a moderate `instrument panel` density across the product. Navigation,
headings and controls recede while documents, answers and operational data own
the viewport. Body and answer typography are not reduced. Desktop controls use
a 36–40 px visual rhythm; coarse-pointer and mobile controls retain a minimum
44 px touch target.

The existing monochrome palette and provenance-line grammar remain the product
signature. Compact density changes hierarchy and geometry, not brand meaning.

## Implementation

- Added a final, application-wide `compact-density.css` layer.
- Reduced topbar from 64 to 56 px, expanded sidebar from 264 to 240 px and
  collapsed sidebar from 72 to 64 px.
- Reduced main gutters from up to 48 px to up to 32 px and vertical main
  padding from 32 to 20 px.
- Standardized page headers at a 28–34 px title scale with tighter spacing.
- Aligned Ask, its composer and the global search to one content spine,
  including the collapsed-sidebar state.
- Reduced the Files catalog to 220 px and converted format filters from two
  large columns to a four-column compact matrix.
- Increased the 1280 × 720 Files canvas from 470 to 538 px high.
- Reduced empty-state and document-assembly headings so they cannot outrank the
  page title.
- Compacted viewer command bars, provenance rails, Files rows, Ask composer,
  Documents, Knowledge Ops and Admin spacing without shrinking body text.
- Preserved 44 px mobile/coarse-pointer hit areas and the one-column mobile
  Files canvas.

## Measured result at 1280 × 720

| Metric | Before | After |
|---|---:|---:|
| Topbar height | 64 px | 56 px |
| Main horizontal gutter | 48 px | 32 px |
| Main vertical padding | 32 px | 20 px |
| Files page header | 102 px | 81 px |
| Page title rendered height | 42 px | 33 px |
| Files catalog width | 250 px | 220 px |
| Format filter | 103 × 40 px | 44 × 36 px |
| Files viewer/layout height | 470 px | 538 px |
| Horizontal overflow | 0 px | 0 px |

Ask global search, page header and composer now share `x = 96 px` in the live
collapsed-sidebar view. The composer remains 960 px wide and body text remains
15 px or larger.

## Acceptance criteria

- Application shell, page headers and main workspace controls use one moderate
  compact-density contract.
- Files at 1280 × 720 has a header no taller than 84 px, catalog no wider than
  224 px, filter controls no wider than 50 px and layout at least 530 px high.
- Ask global search and page content share one left spine.
- Mobile/coarse-pointer primary controls remain at least 44 × 44 px.
- Files, Ask, Documents, Knowledge Ops and Admin remain overflow-free and
  accessible at the supported viewport matrix.
- Unit, lint, type, production build and complete browser suites pass.
