# TIP-026.3 — Completion Report

**Status:** COMPLETE
**Date:** 2026-08-05
**Scope:** Corpus-wide Office glyph recovery, stale-preview governance and
enterprise query-regression hardening

## Outcome

The Vietnamese black-square failure is resolved at the renderer contract,
publication API and existing-corpus levels. The repair is not limited to the
reported Sales Brief: all 11 active DOCX/PPTX versions in the local pilot
corpus now have generator-v3 previews that passed font-embedding, Unicode,
parseability, page-count and checksum checks.

`RtR_Sales_Brief_Template_v1.1_ENG VIE.docx` now opens as a six-page PDF with
the original Word table/layout structure and readable Vietnamese. The active
PDF uses embedded Noto Sans and DejaVu Sans resources and contains no NUL,
replacement-character or black-square markers.

## Root cause ledger

1. The live Sales Brief still referenced an 8,419-byte generator-v1 flattened
   PDF using unembedded Helvetica, Symbol and ZapfDingbats fonts.
2. Advancing the renderer in TIP-026.2 did not invalidate or migrate all old
   Office previews; only the reported PPTX had been recovered.
3. The DOCX Unicode baseline counted merged physical cells more than once
   because `python-docx` exposes merged grid aliases repeatedly. This rejected
   a valid LibreOffice result at 84.98% coverage.
4. Font validation trusted metadata instead of proving that every font used by
   visible text resolved to an embedded PDF resource.
5. The Files API could continue exposing an Office preview generated under an
   obsolete rendering contract.
6. There was no repeatable, audited corpus backfill command.
7. PyMuPDF truncates some span font names, such as
   `LiberationSerif-BoldItalic` to `LiberationSerif-BoldItal`; exact-only
   matching falsely rejected one valid preview.
8. The official integration gate used a stale migration image without the
   production LibreOffice/font runtime and shared mutable Redis test state.
9. Regression testing exposed an independent ontology defect: `timeout` could
   partially match the `time` segment of Real-time Robotics. The prefix rule is
   now one-directional, retaining intentional shorthand such as `Omni` for
   `OmniSight` without matching longer compound words.

## Implementation

- Advanced the ingestion contract to `rtr-ingestion-v3` and Office rendition
  generator version `3`.
- Deduplicated merged DOCX cells by physical XML-cell identity while retaining
  stable table-grid locators.
- Audited fonts actually used by PDF text spans and required every resolved
  resource to be embedded.
- Added robust exact-or-unique-prefix resolution for safely truncated PyMuPDF
  font names.
- Rejected Office conversions that introduce NUL, U+FFFD or U+25A0 markers.
- Made the Files API fail closed for stale Office visual previews and return a
  typed `office_preview_stale` warning while structured text remains available.
- Kept XLSX preview capability correct by including `workbook_manifest` in the
  visual-rendition contract.
- Added a dry-run-by-default corpus repair command:
  `python -m rtr_copilot.commands.rerender_stale_office [--apply]`.
- Routed repair work through durable ingestion jobs, the normal sandbox,
  provenance records and atomic rendition replacement. Originals are never
  overwritten, and a failed replacement cannot displace the prior rendition.
- Isolated the official data-integration gate on Redis database 15 and forced
  its migration/test image to rebuild from the current production runtime.
- Corrected entity-partial matching and added the `timeout` regression case.

## Residual risk

LibreOffice cannot guarantee pixel identity for future documents that depend on
proprietary fonts absent from the approved runtime. This is now a controlled,
fail-closed onboarding concern: a preview with unembedded used fonts, low
Unicode fidelity or introduced replacement glyphs is not published. Extending
the enterprise corpus should be paired with the planned font-governance
registry rather than silently falling back.
