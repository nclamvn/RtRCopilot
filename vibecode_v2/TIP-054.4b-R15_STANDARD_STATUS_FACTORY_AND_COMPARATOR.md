# TIP-054.4b-R15 Standard status factory and bounded comparison

2026-10-09 · Contractor · Vibecode Kit v6.2 · depends on locally verified R14.
The Homeowner requests a standard-runtime factory and comparison before broader
candidate certification. This prospective amendment authorizes a status-private
READ COMMITTED configuration, not a global isolation change or executor startup.

## Task and design decision

Keep the original UnitOfWork and mutation factory intact. For the exact plain
ExecutionService, ActionService, ActionPolicy and shared canonical runtime
factory, status may use a private explicit-RC OptionEngine and plain Session
factory sharing the existing physical pool. Preserve R14's admitted injected
explicit-RC factory unchanged. All other origins keep the original legacy path.

Identity lookup must not initialize a new default engine for an unknown injected
factory. Both standard factory/engine caches must already be populated. Recheck
the original shared factory identity, bound current runtime engine, standard
Session options and empty root engine options on every selection before DB work.
Memoize at most one configuration keyed by the original engine; validate cached
factory, derived view options and shared-pool identity on every use. Tampering or
stale/reset roots selects legacy, not silent repair. Cache no Session, connection,
subject, authority, row, receipt or result. Never dispose an OptionEngine: it owns
the same pool as its parent. Trusted host configuration remains the boundary.

The derived engine sets isolation for each acquired root transaction. Its reset
returns the adapter to the supported initialized/on-connect baseline, not an
arbitrary later committed session setting. Verify ordinary-root isolation before
and after status, including a disposable-database initialized non-RC baseline.
No request SHOW/probe or cached-default-isolation admission credential is allowed.
