# TIP-013 Phase A · onboarding + parity + quality harnesses (synthetic)

Everything here runs on **synthetic fixtures only**. The parity/quality runners
need a **migrated SYNTHETIC database** — never a real corpus — reachable via
`INTEGRATION_DATABASE_DSN`. The real-corpus re-runs are the Homeowner-gated Phase
B (D-013-04, D-013-05).

## Layout

```
eval/
  parity/
    questions.json            # fixed V1-parity question set (committed)
    pilot_fixtures/           # synthetic GOI + prompt + ui.html for the pilot oracle
    parity_report.{md,json}   # generated by `make parity` (committed baseline)
  quality/
    eval_set.json             # representative answer-quality eval set (committed)
    baseline_result.{md,json} # generated by `make eval` (committed baseline)
  lib/
    pilot_oracle.py           # loads the REAL phase-1 pilot answering vs synthetic GOI
    scoring.py                # pure scorer: grounded-rate / honest-null / leak / citation
    harness.py                # V2 seed (publish gate) + ask (RAG path)
  run_parity.py  run_eval.py  # runners (also driven by pytest integration tests)
  onboard/sample_manifest.json
```

## Curator-gated batch onboarding (AC-A2)

Drives a manifest of synthetic source items through the EXISTING gates only —
SOT quarantine→stage→validate→publish and the Refinery import→graduation gate —
dry-run by default, curator-approval-required, two-phase fail-closed, idempotent,
audited.

```bash
# dry-run (validates every item, activates nothing):
make onboard-batch ARGS='--manifest eval/onboard/sample_manifest.json'
# activate (requires explicit curator approval):
make onboard-batch ARGS='--manifest <m>.json --apply --approve --report /tmp/ledger.json'
```

Exit codes: 0 validated/onboarded · 2 rejected (a defective item; zero partial
activation) · 3 approval required (`--apply` without `--approve`) · 4 apply halted.

The manifest references packages the curator has already staged into
`sot_staging_root` / `research_staging_root`; the backend integration test
(`tests/test_tip013_onboard_integration.py`) builds synthetic ones and proves a
clean batch onboards and a defective one is rejected fail-closed.

## V1 parity (AC-A3)

```bash
INTEGRATION_DATABASE_DSN=postgresql://rtr_app:rtr_app_pw@127.0.0.1:5432/<db> make parity
```

Runs each question against the pilot oracle (its real deterministic MOCK
answering, loaded read-only against the synthetic GOI) and V2 (seeded SOT, RAG
path), and writes `parity/parity_report.{md,json}` with answer agreement,
citation presence, honest-null agreement, and a triage of divergences.

## Answer quality (AC-A4)

```bash
INTEGRATION_DATABASE_DSN=postgresql://rtr_app:rtr_app_pw@127.0.0.1:5432/<db> make eval
```

Seeds each case through the real publish/import gates, asks V2, and writes
`quality/baseline_result.{md,json}` with grounded-rate, honest-null-quality,
**leak-count (must be 0 — a leak is a P0)** and citation-accuracy.
