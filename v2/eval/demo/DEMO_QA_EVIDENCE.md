## How the caveat works (implemented in Part A/B, verified live here)

- A **strict** fact (verified provenance + verbatim evidence span) carries
  `needs_double_check = false`; an answer grounded only on strict facts returns
  `confidence_caveat = false`.
- A **soft** fact (verified provenance, no formal evidence span — the value rides a
  `confidence_signal` marker) carries `needs_double_check = true`; any answer that
  cites at least one soft fact returns `confidence_caveat = true`.

Both cases are demonstrated below with real responses.

**Why `/ask` returns honest-null while the fact is retrievable:** the LOCAL
`rag_provider_mode` uses the deterministic **offline extractive** answer stub

prose facts are multi-sentence, so the per-sentence grounding guard
(`factual_unit_ungrounded`) fail-closes rather than emit a partially-cited answer.
Short single-phrase facts (specs, prices above) ground cleanly; long L3 narrative
facts need a composing LLM provider (`rag_provider_mode = external`) to be answered
verbatim. This is a **provider limitation, not a data gap** — the VEGA payload fact is
activated and grounded in the index. Reported honestly per the task's honesty rule.
